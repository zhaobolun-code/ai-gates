# 统一交接模板

每个岗位完成、阻塞或需要转交时，优先使用本模板。项目经理通过此模板判断下一步，避免重复阅读与重复执行。冲突恢复以 **交接时间** 最新为准（见 `state-machine.md`）。

```markdown
## 交接

- **交接时间**：YYYY-MM-DD HH:mm (UTC+8)
- 当前岗位：
- 当前状态：
- 文档状态：
- 车道：
- 当前 Step(步骤)：
- 证据等级：
- 已读材料：
- 已改/已审文件：
- blocker(阻塞问题)：
- 未验证项：
- 新增回归场景（若适用；供 `文档` 同步至 `.cursor/project-context.md`）：
  - 模块 / 场景 / 最低验证步骤 / Console 关键词
- 下一步建议：
- 不要重复：
```

## 填写规则

- **交接时间**（v1.5.1 必填）：写完成交接时的本地时间（UTC+8），用于并发冲突恢复与实施记录对齐。
- **当前岗位**：写 `项目经理` / `策划` / `方案审核` / `程序员` / `代码审核` / `文档` / `周报`。
- **当前状态**：用一句话说明完成、阻塞或待交接。
- **文档状态**：必须与执行文档「文档状态」一致。
- **车道**：Express / Standard / Full（见 [lane-glossary.md](./lane-glossary.md)）
- **当前 Step(步骤)**：写 Step(步骤) 名或 `N/A`。
- **证据等级**：不得高于已实际验证的证据（见 `references/evidence-levels.md`）。
- **已读材料**：只列对判断有用的文件或章节。
- **已改/已审文件**：没有则写 `无`。
- **blocker(阻塞问题)**：无则写 `无`；有则写阻塞格式和解除入口。
- **未验证项**：写需要用户、运行环境或后续岗位验证的事项。
- **新增回归场景**：无则写 `无`；有则填四列，供 `文档` 追加至 ``.cursor/project-context.md`` 运行回归索引（见该文件维护规则）。
- **下一步建议**：写下一岗和原因。
- **不要重复**：写下一位 AI 不要重做的搜索、验证或修改。

## 禁止

- 用交接模板替代真实验证。
- 把 `claimed(已声称)` 或 `static-checked(静态核对)` 写成 `runtime-validated(运行已验证)`。
- 只写“已完成”，不写证据、未验证项和下一步。
- 省略 **交接时间**（并发场景下无法裁决冲突）。
