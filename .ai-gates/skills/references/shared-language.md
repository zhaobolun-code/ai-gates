# 共享语言 / 领域词汇表（活文档）

> 触发：方案、Mandatory、CR 或代码中出现术语歧义 / 同一概念多个叫法 / 中文词与代码符号对不上。
> 出处：mattpocock/skills 的 grill-with-docs / domain-modeling（共享语言 + ADR），2026-08-07 对照落地。

## 原则

1. 术语以**可观察现象 / 代码符号**为准，不以「顺口」为准；一条术语 = 一个概念，禁止同义异名在方案里并行。
2. 词汇表是**活文档**：策划在方案里首次使用新术语时登记；方案审 / CR 发现歧义时登记或改判；程序员不得私下改名。
3. **典故 = 验证智慧的压缩**：典故词是**经方案审 / CR / 验收验证过的既定共识**的压缩包，提词即唤起、不必复述全文；本质是**可信共识的压缩**，不是省 token 的摘要——摘要未经验证、可能失真，禁止拿典故词当『顺手缩写』用。错题本与典故的共同目标见典故节 **一错不二犯**。

## 放哪里

- **通用典故**（系统架构层共识）：本文件典故节。压缩包只写决策层/真源/对照/重设计；**禁止**以本仓窗号、场景 ID、模块特化当主体。
- **项目典故**（本仓实际问题）：`design-patterns.md` 或 `.cursor/project-context.md` 项目口诀。
- **错题本**与典故正交：坑走 [lessons-learned.md](./lessons-learned.md)，禁止把错题行抄进本表典故节。四格与 Skill 自进化 → [pattern-harvest.md](./pattern-harvest.md)。
- 通用 Skill 不写死业务术语（见 [project-local-config.md](./project-local-config.md)）。
- 方案级：仅当术语是本次方案引入且项目表未覆盖时，写进 `未完成.md`「链接」节，结案归并回项目表。

## 登记格式

| 术语 | 定义（可观察 / 可证伪） | 对应代码符号 | 别名（禁） |
| --- | --- | --- | --- |
| [术语] | [现象/行为，一句话] | [类/方法/字段] | [同义异名，禁止再用] |
| Direct（直通道） | **车道**语义（四车道之一）：行为小改（≤3 文件、无 API/持久/跨模块）、策划子窗对话内出 A#/切片**不落盘**、单会话完成；跨会话/改不完自动升 Standard | `CORE.md` §四车道判定 步骤 2；PM YAML `lane: Direct` | 「轻量模式」等 v1 旧称 |
| 双轨调用 | 技能/文档的**调用权限**维度：岗位 SKILL=user-invoked（口令触发，模型不得自动执行岗）；references=model-invoked（触发表按触发自动加载） | `agents/openai.yaml` 的 `policy.allow_implicit_invocation`；`reference-routing.md`「模型自动触发」小表 | 「双轴」（CR 规范轴/规格轴，`dual-axis-review.md`）；「Direct/直通道」（车道语义，`lane-glossary.md`） |
| 并行实现 | 实现层并存路径（同一可观察行为 ≥2 条执行链并存）：互斥 / 降级 / 收敛定义须在 Mandatory/CR 写明 | diagnosis-gates §2.3「并行实现一句」/ §3「并行实现收敛闸门」（流程对象） | 旧词形已全部并入本词（清单见审计决策表 #1 / audit-double-meaning.md） |
| 电路子窗 | 策划写契约时强制拆串联/并联的手续（不是岗）；加速来自墙钟重叠 | `circuit-windows.md` | 「并行实现」（diagnosis-gates §3 代码双轨） |
| 门闸 | 代码路径判断点（放行 / 拦截 / 就绪信号所在处，如 `*_not_ready` 信号） | diagnosis-gates §0.8 预扫链「跳」；与「调用边」成对使用 | 旧词形已并入本词（清单见审计决策表 #2 / audit-double-meaning.md） |
| 瘦身一拍 | 交审前删本 Step 新写/整段重写代码冗余（删除 ≥ 新增）；与技能包「收敛与精简」区分（v3.2 文档精简） | developer SKILL §2.1「瘦身一拍」；project-context 补强三口 | — |

> 「Direct（直通道）」（[CORE.md](../CORE.md) 判定树步骤 2 的车道语义）与「双轨调用」（[reference-routing.md](./reference-routing.md) 的调用权限维度）、「双轴」（[dual-axis-review.md](./dual-axis-review.md) 的 CR 规范轴/规格轴审查维度）、「深模块」（[codebase-design.md](./codebase-design.md) 的设计维度）**不是同一概念**：前者回答「PM 判哪个车道」，后三者分别回答「谁能自动启用该技能/文档」「CR 从哪两个维度审查」「模块接口怎么设计」；禁止混用。
> 门闸 ≠ 诊断闸门：「门闸」是代码路径判断点（预扫链「跳」），「诊断闸门」是流程检查点（diagnosis-gates.md 文档节），成对消歧、非同义。
> 止血 / 复用四问 / 瘦身一拍：三词不同机制（神类增长控制 / 写前复用检视 / 交审前精简），同段出现按角色语境取义；压缩包见「典故」节，本节不重复。

## 争议处理

术语冲突时：主窗 PM 定夺 → 改项目表 → 该术语相关 Step 的 Mandatory 同步；禁止同一 Step 内两套叫法并存（CR 视为 **major**）。

## 典故

辨析表回答「一个概念一个词，防同义异名」；典故节回答「一个词唤起一整段既定共识」；辨析表保留不动。

| 典故词 | 压缩包（提词即唤起、不必复述的全文） | 触发 |
| --- | --- | --- |
| 神类止血 | 神类禁堆逻辑：新逻辑默认落 `*Service` + 一行委托；净增过大须落点改写或同窗 REMOVED；新/重写方法体宜短；Mandatory 用替换句式（仅追加无下沉 → 方案审 major/blocker）；交审前瘦身一拍。有 `.cursor/project-context.md` 神类止血节则按该节的阈与落点。 | 方案/CR 触及神类文件时点名即唤起，不复述阈值 |
| 复用四问 | 已有吗→能复用吗→能少写/不写吗→能删吗；写 Mandatory 前强制，未检索不得写新路径。出处：`.ai-gates/skills/references/execution-discipline.md` §复用四问 | 写方案/改码/扩 README 前点名即唤起 |
| 双轴 | CR 从两维审：规范轴 = 与仓库规范一致性（CORE / 岗位 SKILL / README 硬约束，应当怎么写）；规格轴 = 与本次规格一致性（A# 覆盖未越界 / Delta Spec 落实 / DO NOT TOUCH 未碰，这次要做什么）；findings 按轴分组输出。出处：`.ai-gates/skills/references/dual-axis-review.md`（与「双轨调用」「Direct」是不同维度，见辨析注记） | CR 场景点名即唤起 |
| 深模块 | Depth 是接口属性非实现属性；Interface=调用者须知一切；Seam 位置是独立设计决策；删除测试；一个 adapter=假设的 seam、两个=真的；词汇 8 词逐词禁止漂移。出处：`.ai-gates/skills/references/codebase-design.md` | 设计模块形状/找 seam/接口方案对比时点名即唤起 |
| 改坏即错刀 | 系统改动须让可观察行为变好。改前钉对照；改后整体变差则本刀为错，定向撤，禁止再叠补丁。局部条款变绿不算向好。撤不回对照则禁止换皮再试。 | 热修/修 bug 后整场比改前更差，或局部绿、系统恶化 |
| 连败先问重设计 | 同一系统目标连续失败时，先停补丁，检查决策层是否多真源互相打架或被架空，要不要重设计。重设计=删并行决策、只留一个真源，不是再加一层控制。一次失败不等于推倒整套。 | 同一目标连续测挂、换层、热修仍不过，或越修越糟 |
| 一错不二犯 | 犯错不可怕；可怕的是重复同一错误。错题本记坑（错因+改正），典故记已验证的结构/共识。写方案与热修前先扫对应格，禁止同一手法换皮再来。记表不是目的，目的是同一错不二犯。 | 写 Mandatory 前、换窗热修、准备再叠同一手法、沉淀入表时 |
| 入表不是岗 | 项目格已准 → 去上下文化 → 可传队列 → 抽象草稿 → 另「准」才进通用格（典故进本文件 §典故，错题进 anti-patterns）。模式沉淀 / 电路子窗 / 本地环都是入表手续，不是岗。禁止第七岗、禁止静默入表、禁止「准」自动入通用格。 | 写 Mandatory 前、想开新岗收知识、准备把项目坑抄进 Skill、热度满想自动入典时 |
| 使用与入表拆开 | 用词条看症状：对上就按结构配方落地（有现成入口则复用，没有则按配方做第一份）。登记看锚点：有真代码证据才写入验证格。一次性私有播放不算成熟实例。按结构配方做，不要抄别的仓库的类型名。出处：`design-patterns.md`「使用 vs 入表」 | 写方案扫症状表、空白项目第一次落地、准备把一次性门当成熟实例复用时 |
| 自注册、只认接口 | 中央循环要处理一个会增长的对象集合，每种对象对同一问法的回答不同。引擎只认一套接口：无副作用的探测，加上只往输出里追加结果的处理；对象自己成对登记进出。新种类只实现接口并注册，不要改引擎去点名类型。探测步骤禁止改状态。只有一种已知对象时不必套协议。同一对象换算法、成对交互的生命周期、外形适配、整树同形，都不是本条。不要简称成调度器，以免和「订阅推送」混挂。按结构配方做，不要抄别的仓库的类型名。 | 写方案时中央循环开始按类型名分叉，每加一种对象就要改引擎 |
| 订阅推送 | 一处事实要通知多处，变更源不关心谁响应、不必拿返回值。有现成分发入口则复用（成对登记与解除，分发时快照听众）；没有则对象局部一对多即可。禁止新开第二套全局总线。只通知一个固定对象 → 直调。同一步须保序或拿返回值 → 直调。回调内禁止再改主题状态。禁止每步全量广播。开放集合接入引擎、同一动作换算法、成对交互的生命周期、外形适配、沿路截办，都不是本条。按结构配方做，不要抄别的仓库的类型名。 | 写方案时一处变化要通知多处，且不需要返回值 |
| 可撤销入栈 | 用户操作须可撤销/重做，或把「做了什么」从当场改状态拆开再入栈。有现成入口则复用（执行/撤销/重做 + 撤销与重做双栈）；没有则按该配方新建。禁止第二套撤销栈。只要返回值或同一步必须保序 → 直调。一次性内部调用不需要撤销 → 不要套壳。热路径判定不要包进可撤销入栈。成对交互的生命周期、同一动作换算法、订阅推送，都不是本条。按结构配方做，不要抄别的仓库的类型名。 | 写方案时用户操作要可撤销/重做，或要把动作从当场改状态里拆出来 |
| 共享生命周期 | 多种对象之间一种交互共享「能否交互 → 执行」生命周期，差异只在执行体。有现成入口则复用（调度方只调执行）；没有则按该配方新建。禁止为单一对象新开平行调度器。一次性内部直调、不需要这套生命周期 → 不要套。输入设备不要写进执行体。同一动作换算法、外形适配、可撤销入栈、订阅推送，都不是本条。按结构配方做，不要抄别的仓库的类型名。 | 写方案时多种对象要走同一套交互生命周期，彼此只差执行体内 |
| 按类型创建 | 按键创建、单一产品种类。有现成单一创建入口则复用；没有则按配方新建（查配置再构造）。禁止第二套平行 new。已知唯一类型的一次性 new 不必套。不要升成可切换的工厂族。视觉颗粒实例化、成对交互的生命周期，都不是本条。按结构配方做，不要抄别的仓库的类型名。 | 写方案时多处要按类型或配置造出同类对象，调用方不应自己查表再 new |
| 外形适配 | 同一种效果要贴到多种外形，且多种效果共用一个生成入口。有现成入口则复用（单一生成入口 + 按类型注册 + 随外形适配/更新）；没有则按该配方新建。禁止第二套生成器。已知唯一对象+唯一效果的一次性改位置不必套。开放集合接入引擎、同一动作换算法、成对交互的生命周期、叠衣增效，都不是本条。按结构配方做，不要抄别的仓库的类型名。不要引进别的仓库的适配器类型名。 | 写方案时同一种视觉效果要贴到多种外形，或新效果要进同一套生成入口 |
| 同一动作换算法 | 同一动作可换算法，调用方保持一句。有现成入口则复用（同一动作接口 + 可替换实现 + 调用方只调接口）；没有则按该配方新建。禁止第二套平行算法分叉。已知唯一算法的一次性直调不必套。判定可枚举化（门态/组成选枚举）不是本条。成对交互的生命周期、外形适配、开放集合接入引擎、换态易行、沿路截办、叠衣增效，都不是本条。按结构配方做，不要抄别的仓库的类型名。 | 写方案时同一动作要按不同算法完成，调用方不应在体内按算法分叉 |
| 整树同形 | 单个和整棵要同一套操作。有现成入口则复用（叶子与容器同一接口，遍历只走该接口递归）；没有则按该配方新建。调用处禁止用类型判断区分容器与叶子。新节点只实现接口，禁止改遍历方。列表一遍扫描、中央循环按类型分叉（自注册、只认接口），都不是本条。按结构配方做，不要抄别的仓库的类型名。 | 写方案时单个和整组（树状层级）要同一套操作，调用方不应区分叶子与容器 |
| 叠衣增效 | 不改原对象核心，层层包裹追加行为。有现成入口则复用（构造接受被装饰者，禁止装饰器自己创建它；禁止改被装饰者私有核心）；没有则按该配方新建。能改原类一行或加一个组件就完 → 不要套。层数把调试看不清就停。同一动作换算法、外形适配、成对交互的生命周期，都不是本条。按结构配方做，不要抄别的仓库的类型名。 | 写方案时要在不改原对象核心的前提下动态追加行为 |
| 沿路截办 | 请求沿一串处理者走，谁认谁办、办完即停。链只在一处组装。禁止当广播（订阅推送）。禁止改完请求原件再往下传（要改就显式另造一份）。只有一个固定处理者 → 直调。调用方选定算法（同一动作换算法）不是本条。语言捕获异常不是本条。按结构配方做，不要抄别的仓库的类型名。 | 写方案时请求要沿多级过滤或校验走，谁认谁办、办完即停 |
| 换态易行 | 对象内部阶段一变，同一操作整套行为跟着换。行为只委托给当前状态对象；切换由状态对象或上下文统一入口发起，禁止外面改完状态值再调行为。上下文禁止按当前阶段写硬编码分支。同帧互斥/只读快照（项目词条 State 快照）、门态枚举判定（项目词条 Policy）、调用方换算法（同一动作换算法），都不是本条。按结构配方做，不要抄别的仓库的类型名。 | 写方案时对象有明确阶段，且不同阶段下同一操作整套表现不同 |

**漂移防护**：典故词条禁止静默改义——压缩包内容或触发语义变更，须更新登记表对应行并同步引用文档（与 §争议处理 同构：主窗 PM 定夺 → 改表 → 相关文档同步）；口头改义不落表 → CR 视为 major。

**活跃度三态（典故 / 错题 / 反模式共用）**：判据权威 → [lessons-learned.md](./lessons-learned.md) §时效归档。**高频 → 升级候选**（近 90 天 ≥2 次命中且最近命中 ≤30 天，走机制 B）。**稳定 → 维持**（近 6 个月有命中且未达升级资格，保持可见）。低触发降级见下段。

**低触发降级**：典故词条近 6 个月无点名（低触发）→ **保留原文**、标 `[低活跃]` 并**落盘移注**——降级词条须登记到项目级（`.cursor/project-context.md` §领域词汇表）或本文件「归档」节，注明降级时间与原因；**仅口头声明 / 仅标低活跃不构成降级完成**（CR 视为 major）。漂移防护句不受影响：词条在任何状态下均禁止静默改义。
