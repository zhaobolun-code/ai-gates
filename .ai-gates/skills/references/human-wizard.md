# 人机交互向导（可选 · 只能人做的步骤）

> 触发：步骤只有人能完成（凭证 / 密钥 / 授权 / 第三方后台 / 物理操作 / 发布审批），agent 不能代跑时。
> 出处：mattpocock/skills wizard（交互式向导），2026-08-07 对照落地。

## 原则

- Agent 能自己做的 → 不做向导；向导只用于「必须人做」的步骤，禁止把可自动步骤推给人；
- 向导 = 逐步可执行清单（含预期结果与失败判据），不是让用户复述文档。

## 结构（一页内）

1. 目标与前置：这条命令 / 步骤要达成什么、前置条件（环境变量 / 权限 / 路径）；
2. 逐步操作：每步 1 行命令或 1 个点击路径 + 「预期看到什么」；
3. 失败判据：什么现象算失败、失败后怎么办（回滚 / 重试 / 上报）；
4. 回报：人执行完回报「完成 + 结果摘录」；Agent 核验后继续，禁止默认成功。

## 常见适用

- 申请 / 轮换 CI 密钥、登录第三方后台、授权 OAuth、配置 IDE / Unity 激活；
- 一次性迁移 / 割接中只能手点的步骤；物理操作（接管线 / 放样）。

## 边界

- 涉及密钥时：向导不要求用户把明文贴回对话；只回报「完成 / 失败 + 可验证的非敏感结果」；
- 向导步骤失败 → 停住交 PM，禁止 agent 猜测绕过。
