# 用户确认要点（一轮确认 · 强制白话）

> 权威：凡需用户拍板的内容均遵守本文件。
> 技术钉死在 `Mandatory-*.md` / A#，**不**因白话而变虚。
> **硬律**：每个决策点 **只 1 轮确认**；细则与自动手续 → [handoff-automation.md](./handoff-automation.md) §0。
> **拍板口令**：确认包正文只写 **「准」**（可附「或回复按推荐」）。禁止在确认包里教「开干」「做吧」「听你的」。
> 「准」= 定版+改码；**不**自动 `gh issue create`、**不**自动写入收集仓（[collect-queue.md](./collect-queue.md)）。

## 目标

用户只看现象与选型就能拍板；**一句「准」**后 Agent 同条干完手续。
**禁止**「理解正确 → 确认方案 → 开始改码」或「开窗 → 再开始改码」等多轮空转。

## 需求澄清三问（模糊词 → 硬指标 · 与「最多 1 轮」兼容）

需求含模糊词（「优化性能」「改顺畅点」「更稳定」等）且影响车道/验收时，用三问把模糊词量化；
**三问合计 1 轮**，答不全按默认决策继续（与 §判定前一致）。问答产出直接进物理口径 / A#，
禁止只留在对话里。

- **Express**：只问最关键 **1 问**（通常为①目标量化）。
- **Standard / Full**：完整三问。

① 目标量化：「你所说的 <模糊词>，具体指哪个指标（如 `/api/list` 响应时间 / 首屏加载时间）？
   当前数值多少、目标多少？」
② 负面约束：「改动过程中是否允许改变现有接口 / 字段 / 结构？（如返回字段名、存档格式）」
③ 验证环境：「改完在哪个环境验证算过关？（本地 / 测试环境压测 / 预发布）」

产出示例：`将 /api/list 响应时间从 200ms 降至 ≤150ms，且不改变 JSON 字段名；测试环境压测通过即验收。`

## 异步问卷（可选 · 决策留给别人的时候）

> 触发：决策只有某个人能答（另一团队 / 合作方 / 审批人），且不适合当场 1 轮对话时。
> 出处：mattpocock/skills to-questionnaire，2026-08-07 对照落地。

- 问卷只问「对方必须拍板」的问题，不问 agent 自己能查 / 能推的；
- 结构：背景（≤3 行）→ 决策点（单选 / 多选 / 数值，各附一句默认）→ 需要对方回传什么；
- 产出 Markdown 文件（`证据/questionnaire-{主题}.md`）或消息，异步填完回传；
- 回传后按「一次确认包」继续，禁止把问卷当无默认的空洞提问。

## grill 访谈（可选 · 需求未定的深度澄清）

> 触发：需求切片**未定**且命中任一——需求模糊（多条设计分支未决）/ 大需求（wayfinder 级设计树）/ 多次澄清（三问或条件触发 1 轮）后仍分歧 / 领域词需当场定名。
> 出处：mattpocock/skills grill-me / grilling（2026-08-11 对照落地；领域词产出由 shared-language 典故机制承接；与 [[shared-language]] 出处的 grill-with-docs 为不同 skill）。

- **一次一问**：Agent 每轮只问 **1 个**问题，用户答完再问下一个（原版为每轮问整个 frontier 问题集；落地取一次一问，对用户打扰最小）。不选批量：一次甩整个问题集 → 用户决策负担大、易跳答，与『最小打扰』取向冲突。
- **分支穷尽才动笔**：继续问直到设计树全部可问分支走完、无静默假设；未穷尽前禁止写切片 / Mandatory。
- **问题须有证据支撑**：问前先查代码 / 文档 / README，只问「用户必须拍板」的决策；Agent 自己能查的事实（文件、接口、数值）不问用户——与异步问卷「不问 agent 自己能查的」同律。
- **每问带推荐答案**：问题须含默认 / 推荐选择；用户「你决定」→ 按推荐继续（对齐「禁止把问卷当无默认的空洞提问」）。
- **产出**：① 澄清结论直接进物理口径 / A#（禁止只留在对话里，对齐三问）；② 领域词按 shared-language.md 登记（通用典故进 shared-language 典故节；项目术语进方案「链接」节一行，结案归并项目表）。
- **边界**：grill 澄清轮数不受「最多 1 轮」限制，但仅限车道/范围已定、**切片未定**阶段；判定前仍走 CORE「最多 1 轮」追问（≤3 问，答不全按默认决策继续），不改 CORE 字面；拍板确认仍限 1 轮；grill 结束后的**一次确认包**仍是 1 轮；命中「决策留给别人」→ 不走 grill，走异步问卷。

## 一次确认包（开始改码 · 强制默认）

方案审无 blocker（Express：切片已写）后，**一条**消息：

```text
请一次确认（通过后定版并开始改代码）：

【核心理解】
1. 【现在怎样】……
2. 【改完应该怎样】……
3. 【仍允许停住】……（若有）
4. 【怎么判断修好了】……
5. 【这次不修】……

【本步方案】选：……
【为什么】……（≤3 句）
【不选】Y / Z（或「无其它合理候选」）

【推荐】「准」→ 定版+同条改码+默认 Auto（连跑至待测；测挂默认同条跟可自动跟推荐，硬停除外；每 Step 仍要测）。
「准, 不 Auto」→ 只做当前 Step。禁多轮确认。
（Express：无 Auto 句；「准」只改本切片。）
```

| 要 | 不要 |
| --- | --- |
| 改前写清方案/为什么/不选的 | 先改码再补理由 |
| 「准」= 理解+方案+开始改码全部确认；Standard/Full 默认 Auto | 再问理解/定版/开始改码/是否 Auto |
| 「准」后走 handoff §F（含默认 Auto） | 零用户句改码 |
| 确认包教「准」+ 退出/后果 | 教「开干」「做吧」；Express 误开 Auto；暗示每步再选型 |

**顺序钉死**：Mandatory + 选型 → 方案审 → **再**发本包 →「准」→ 改码。
禁止未过方案审（Express 除外）因「准」改业务代码。

## 续链合并包（强制 · 禁止拆两轮）

窗已签收且仍有下一刀时，**禁止**「请说开 γ」。须发 **合并包**（开窗+本步方案+开始改码，仍只问一轮）：

```text
本窗已验收。【续链一次确认 — 开窗+本步方案+开始改码】

【本窗结果】……
【推荐下一步】开 γ：……（目标一句）
【为什么】……
【不选推荐】先停 / 另开需求：……

【本步方案】选：……
【为什么】……
【不选】……

【推荐】「准」→ 同条开窗并改码+默认 Auto（连跑至待测；测挂跟可自动跟推荐，硬停除外）。
「准, 不 Auto」→ 只开窗做当前 Step。禁多轮确认。先停直接说「先停」。
```

「准」后走 [handoff-automation.md](./handoff-automation.md) §G：建窗 → 方案审（若需）→ **无 blocker 则直接改码，禁止再发改码确认包**。
仅当方案审后选型**实质变更**时，才允许再发 **1** 条新确认包。

## 白话规则（强制）

| 要 | 不要（主句禁止当主信息） |
| --- | --- |
| 看得见的现象 | 变量名 / API / 阈值当主句 |
| 「高压在推但液不动」 | 只甩 eq/raw 黑话 |
| 「这次不修浸没阀反向」 | 甩缩写不解释 |

**自检**：删掉代码符号后用户能否判断对错？不能 → 重写。
允许括号附「实现上对应 xxx」。

核心理解**只嵌在**一次确认包 / 续链合并包内；**禁止**单独先问一轮「理解正确吗」再发包。

## 多选决策（亦算该决策点的唯一一轮）

Verify 失败 / 止损等须二选一时：

**Auto 且推荐 `auto_follow: yes` 且未硬停**（见 [diagnosis-gates.md](./diagnosis-gates.md) §0）：**不发**本多选确认包；同条跟【推荐】并留据。硬停 / 非 Auto / `auto_follow: no` 才用下方形态。

```text
A. ……
B. ……
【推荐】A
【为什么】……
【若不选推荐】……
也可「准」。
```

开始改码/续链类拍板用上方确认包，**不要**再拆成多个多选。
非 Auto / 硬停：写出【推荐】≠已代选；须等用户句。超时 → 停在「待你确认」。
止损将到 2/3 或触顶（diagnosis §0.7）：【推荐】仍是 A#/口径复议；确认包**另附**一句可选「回完整碰撞则启用思考碰撞（不替代复议）」。未点名不跑。热度爆炸条件见 [collision-review.md](./collision-review.md) 用途分级「提示」。

## 需求澄清（条件触发 · 最多 1 轮）

仅当 ≥2 种合理解释影响车道/范围等时追问 ≤3 条；用户「你决定」→ 默认继续。
**不**与开始改码确认叠成两轮：澄清答完后写方案审，再发一次确认包。

### 触发条件（命中任一才追问）

- 需求 **≥2 种合理解释**，且会导致不同车道/改动范围
- 涉及体验判断且 README/context 推不出唯一方向
- 现象缺关键复现信息，无法判断改动面

**不触发**：已明确文件/行为/验收、纯咨询、已有方案仅要求继续。

## 岗位要点

| 岗位 | 动作 |
| --- | --- |
| 策划 | 交审前选型短表；过审后发**一轮**确认包（正文只写「准」） |
| PM | 只保留一轮确认自动化；续链用合并包；禁口令门与口语口令 |
| 方案审 | 缺选型 → major；要求用户再确认一轮才定版 → major |
| 程序员 | 无「准」类确认或无选型 → 不得改码 |
