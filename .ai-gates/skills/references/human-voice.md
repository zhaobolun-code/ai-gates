# 书写习惯

每轮写给人看的话用这份。进度说法仍以 [user-visible-states.md](./user-visible-states.md) 为准。周报骨架和删腔仍以 [weekly-report.md](../templates/weekly-report.md) 为准。模块 README 该有的节仍以文档岗为准。

这份不管检测器。命令、路径、链接、表头、代码，不要为了顺口改掉。

## 写的时候

先写这件事本身。读者已经知道的，不要再讲一遍。缺数字、人名、日期，写还不知道，或者去问。

一句能说完，就不要先否定一句再转折。

别这样：这不是又一套技能清单，而是一套项目里的规矩。

这样写：它管的是这件事该不该先停一下。

段尾不要再补一句金句。上一句已经说完，就停。不要凑成三项。有两条写两条。不要先垫话。「说实话」「简单来说」「让我们看看」删掉。不要跟没人提出的反对意见辩论。

结尾停在最后一件事实。句子长短跟着意思走。一句很短，可以单独成段。

假深沉换成具体的事。「深入」「赋能」「闭环」「抓手」「落地」「对齐」改成做了什么。只换词不够。换完读一遍，还是同一节奏，就重写这一段。

加粗只留给读者必须看见的那几个词。不要「好问题」，不要「希望这对你有帮助」。

## 中文

换到任何题目都能用的开头，删掉。

别这样：随着人工智能的不断发展，开发流程已经发生了深刻变化。

这样写：AI 改完常常说做好了。你一试，旧配置打不开。

事实说完，不要再挂「体现了」「彰显了」「进一步凸显了」。「标志着」「奠定了坚实基础」「翻开了新篇章」改成那件事本身是什么。

「对反馈进行深入分析，对功能作出调整，对问题予以解决」写成「看反馈，改功能，把问题处理掉」。周报要书面时，留一处「进行」可以，不要三处连着来。

英文句子的骨头留在中文里，要拆开。一串「的」叠在一起，拆短。一个成语不用删。四个四字词对仗排开，才要拆。

没有明显好处，就别改这句。代码、命令、数字、「可能」「计划」「已经」这些词的意思不能为了顺口换掉。

不要装成聊天。不要编一段「我当年」。不要每篇都加「说白了」「靠谱」「吧」「嘛」，也不要故意写错别字。首页可以对着人说，周报和模块说明保持书面。

## 写完读一遍

问三句。

第一句是不是这件事本身。

有没有哪句只是在重复上一句。

有没有哪句是为了显得像人，才加上去的感叹。

还有腔，就改那几句。不要整篇换成更华丽的词。
