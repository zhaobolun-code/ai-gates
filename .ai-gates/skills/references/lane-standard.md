# Standard

写给人看的话之前先读 [human-voice.md](./human-voice.md)。它不占参考文件的两份名额。命令、路径、表头、周报骨架不改口吻。

1. 开方案和热修扫错题大纲。问句和点名改法不扫。命中写日期或关键词一行。
2. 一个方案夹。活跃正文在 `未完成.md`。复用四问、选型、可证伪 A#、Delta 写在当前 Step。
3. 方案审没有 blocker，再发一次确认包。包里只写「准」。
4. 「准」之后派程序员子窗，显式 `model=`。
5. 普通 L1 改完由主窗同会话做只读 CR，并标「非独立 CR」；此路径不要求子窗或 `hooks-log/cr-stamp.json`。L1.5/L2、Full 或高风险 CR 按 [isolated-review.md](./isolated-review.md) 优先隔离；只有隔离审核子窗可写 CR 戳记，缺戳不得标成「隔离复核已完成」。业务 C# 的交审材料要有可执行的 Unity 步骤或 Console 关键词；没跑就写 `not run`。
6. 这一刀含业务 `.cs` / `.lua` 且还要人测：运行 `scripts/set-knife-state.ps1`，写下待测、窗名、A#、现象句、热修次数、当前车道。同一窗、同一 A#、同一句现象再热修，次数加一。

有 blocker 不定版。用户确认完整流程，改读 `lane-full.md`。

要读代码或长文档、要搜索仓库、要跑终端、要看日志，先打开 `read-evidence`、`run-evidence`、`log-evidence` 里对应的一份，再派子窗。主动搜索排除 `.ai-gates/tmp/`，已经点名的路径仍可读。派发只写岗位、轮次、派发文件路径。不贴哈希、预期哈希、blocker 原文、岗位卡。子窗交回只留三行。实现子窗自己读岗位卡。隔离审核子窗不读常驻卡，只读派发白名单。主窗不改 `证据/_方案审核派发.md` 和 `证据/_StepNN-代码审核派发.md`。

同一方案夹，且口径、选型、A# 相对上一刀没变：不派方案审，派发写 `campaign: yes` 和上一刀 Step 号。两步及以上、文件不相交、没有 depends-on：同一回复里一起派。有依赖或抢同一文件才一个接一个派。禁止续问同一个子窗。再查就新派，提示只含这一问。细则在 `circuit-windows.md`，用到才打开。
