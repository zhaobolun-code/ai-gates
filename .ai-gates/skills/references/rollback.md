# 回滚指令（方案推翻）

> **触发口令**：用户说「方案推翻」「思路不对，重来」「这个方向不对，撤回改动」等。与「按 CORE 重来」（流程纠偏，不动代码）是两条不同的口令——本文件专指**撤销本轮已落地的代码改动**。

## 流程

1. PM **先确认范围**（用户可见）：列出本轮/本 Step 已改动的文件清单，问一句「确认要撤销以上文件的改动吗？（确认后会列出 `git checkout --` 精确命令，请你在终端执行；丢弃未提交修改，无法找回）」
2. 用户明确确认后，**列出精确命令**请用户在本机终端执行（复制即可）：
   ```powershell
   git checkout -- <本轮改动文件列表>
   ```
   Agent **禁止**经 Shell / 工具调用执行 `git checkout --`（hooks `git-safety-check.ps1` 对 Agent 侧一律 deny，这是故意的）。**仅回退列出的文件**，不得建议 `git checkout .` 或 `git reset --hard` 扩大范围；已 `git add`/已提交的改动需额外确认是否连带回退，不确定则只列出**未暂存**文件并如实说明。
3. 回退后，PM 交回 `[planner]`（Standard/Full）或直接在 Chat 内重新出 express-slice（Express），并在**你下一步**说明"已撤销 [N] 个文件的改动，原方案已废弃，将重新出方案"。
4. **记录**：追加一行到 `.ai-gates/pipeline-recovery-log.md`（偏差类型记 `方案推翻`），写明推翻原因（一句话）与涉及文件数，避免下次同类方向重蹈。

## 边界

- **不属于**硬门禁 7 条范畴，是用户主动纠偏的快捷通道；PM 仍需遵守 Git 安全底线——**任何回退前必须显式征得用户确认**，未确认不得执行。
- 若改动已推送到远端或已被其他协作者拉取，`git checkout` 无法处理远端历史，需提示用户手动协调，不得代为 `push --force`。
- 回退不等于"流程走歧了"，不必走 §Agent 失败模式与恢复 的完整恢复表；但若同时存在"缺 PM 判定"等流程偏差，两者可以在同一轮一并处理。

## 记录格式

复用 [pipeline-recovery-log.md](../templates/pipeline-recovery-log.md) 表格，偏差类型列填 **`方案推翻`**，备注列写推翻原因摘要。
