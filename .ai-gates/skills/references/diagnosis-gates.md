## 0. Verify 失败后的默认推荐（强制）

触发：用户回复测试不通过 / A# 失败 / Console 证伪当前主修假设。

### 0.1 禁止

- **禁止**默认「再开 Step N+1 / 直接改码」且不经本文件 §0 矩阵选推荐。
- **禁止**静默代选（默认）：未收到用户回复（选项字母 / 「准」等）不得开写方案或改码——**例外**：本窗 **Auto 启用**且 §0.3 该行 `auto_follow: yes` 且未命中硬停 → 允许同条代选【推荐】（须留据，见 §0.4）。非 Auto / `auto_follow: no` / 硬停 → 仍禁静默代选；每个决策点只 1 轮确认（handoff §0）。
- **禁止**跳过白话现象摘要，直接甩 API 黑话选项。
- **禁止**在已命中 §1 止损（含热修累计）时仍推荐「再开热修 N+1」。
- **禁止**默认让用户整段粘贴 Console：**先**按 [unity-editor-log.md](./unity-editor-log.md) §B 查 `Editor.log`；不够再请补测/短摘录。贴命令/日志/产物前，密钥与 token 写成 `<REDACTED>`；只引信号行。禁止整段贴未脱敏 log。
- **禁止**规格漂移：根因改判后不先更新 `物理口径.md`/A# 就直接开码（见 §0.5）；开码前属硬停。
- **禁止**异现象并修：Discover 已钉死「可见症状 ≠ 本窗 A#/目标」时，仍在本窗堆 Step/热修，或把本窗止损误计到 3/3（见 §0.3 异现象行；outcome 记 `why_multi=scope`）。
- **禁止**验挂红自动 `git reset --hard` / 无脑整库硬回滚；无意义时只做**定向撤**（本 Step Mandatory 业务 diff / 停用有害 API）。
- **禁止**用批量回归/黄金场景绿（含项目配置的场景 ID，或同类假绿）当「本刀有意义」依据；有意义只对照 A# / 可见现象 / 本刀假设。
- **禁止**跳过有意义评审直接同 A# 热修/改码；评审为「无」或「测偏」后**禁止**同 A# 再热修（须换思路 Discover）。

### 0.1.1 硬停白名单（`auto_follow: no` · 必须等人）

命中任一条 → 发确认包，未「准」不得开热修/改码：止损触顶 / `fuse`（含热修上限、`max_repair_rounds`）→ **须 A#/口径复议**（确认包按 §0.7 **提示**可选完整碰撞）；异现象挂起另开窗；规格漂移开码前；`discover/replan/scope_change/lane_upgrade` 范围外扩；推荐会改已批准 Mandatory 外的模块/物理边界；**止损将到 2/3**（当前已为 1/3 且本轮失败将计至 2/3，或已写明即将 2/3）→ `auto_follow: no`，先做完有意义评审，再确认包等「准」（**同样提示**可选完整碰撞）。

### 0.2 决策顺序（内部）

```text
Verify 失败
  →【自动】方案夹 `未完成.md` → ## 错题 L0 草稿（不问用户；禁写主表；见 lessons-learned §准全自动）
  →【自动】追加 `证据/_repair-blackboard.md` 一条（§0.6；无则按模板创建）
  → Discover：≤5 行白话现象（须对照黑板最近 ≤3 条，禁换皮重试）；质量/体积/浓度/亮度异常须从该物质生成点起查（§0.2.2）；拟改门闸/放行/改道 → 须 §0.8 全路径预扫
  → 优先查 Editor.log（关键词检索，≤15 行摘录；见 unity-editor-log §B）
  → 对照本窗 A#/目标：是否异现象（§0.3）
  → 对照止损计数（§1）与 repair_rounds/fuse（loop-engineering）
  →【强制】有意义评审（§0.2.1；三选一写黑板；再改码前）
  → 按 §0.3 选出【默认推荐】（含 auto_follow；仅评审为「有」或「部分有」且仍属同 A# 可修时才可进热修/切片行）
  → Auto 且 auto_follow=yes 且未硬停：同条执行【推荐】+ 留据（不发多选）
  → 否则：「你下一步」多选：推荐 + 为什么 + 不选后果（须等用户回复）
```

### 0.2.1 有意义评审（强制 · 再改码前）

对照 **本窗 A# / 可见现象 / 本刀假设** 三选一写黑板（字段见模板 / §0.6）；**禁**以批量回归/黄金场景绿、CR 绿、`static-checked` 冒充有意义。**钉死**：批量回归绿 ≠ 有意义评审 ≠ 业务 A# 手测签收（若 project-context 配置了 §热路径批量回归，结案前仍须跑表内场景，但不得拿绿冒充 A#）。验挂后、再改码前必须**点名本刀红/绿信号**（EditMode / PlayMode / Console 关键词 / 脚本化断言）；没有 → **停在 Discover**，禁止盯代码开热修。Unity 现象项仍可为人看见的 Console/步骤，但必须点名，禁止空口「先读一圈」。禁止另开第二套 Discover。

| 结果 | 动作 |
| --- | --- |
| **有** | 保留本刀；黑板写保留原因 +「下一刀不得重复什么」；才可进入 §0.3 同 A# 热修/切片推荐行 |
| **无** | **定向撤**本 Step Mandatory 业务改动（revert 业务 diff / 停用有害 API；**禁止** `git reset --hard`）；黑板记「已撤」+ 范围一句；**禁止**同 A# 再热修；须换思路 Discover（重钉出口层 / 口径复议 / 拆合取） |
| **部分有** | 只留诊断日志；功能旁路撤掉；黑板记「已撤」功能侧 + 保留诊断侧；功能侧禁同手法热修 |

「测偏」（本刀未打到本窗 A#/现象）按 **无** 处理：定向撤 + 禁同 A# 热修 + 换思路 Discover。

### 0.2.2 从物质生成点起查（质量/体积/浓度/亮度异常）

质量/体积/浓度/亮度异常 → Discover **从该物质生成点起查**（配置生成、拆分、入瓶），再倾倒/传递，最后才观察层。点不出生成/拆分上的写入事件 → **禁止**把观察层补偿公式（灯/阈值/减账本/extra）当唯一改点；方案以观察层公式为唯一改点 → 方案审/CR **blocker**。**禁止**先改观察层公式当唯一改点。岗文禁止写本仓窗号。

### 0.3 默认推荐矩阵（唯一推荐）

| 条件（按上到下，命中即停） | 【推荐】 | `auto_follow` | 白话理由要点 |
| --- | --- | --- | --- |
| 命中 §1 止损线 **或** `fuse reason=max_repair_rounds` | **A#/口径复议**（止损重定界） | **no** | 禁止同 A# 再堆 Step/热修/交审修复；须确认包改边界或改 A# 后再开刀 |
| Discover 钉死：可见症状 **≠** 本窗 A#/目标（异现象） | **挂起本窗 + 另开短窗** | **no** | 禁并修；本窗止损冻结（勿误烧 3/3）；新窗写自己的 A#；outcome `why_multi=scope` |
| 根因**未**钉死（仍可能多解释 / 缺关键日志） | **只读排查（Discover）** | **yes**（Auto 时） | 先搞清卡在哪，再决定是否开窗；只读落钉点，不改码 |
| 根因已钉死，且属 §2 热修范围，**且未触 §2.1 热修上限** | **热修短窗** | **yes**（Auto 时；须仍在已批准物理边界内） | 独立短窗，不塞主 Full 年表 |
| 根因已钉死，属主现象下一切片且未触止损 | **开下一切片短窗** | **yes**（Auto 时；须仍在已批准 Mandatory 内） | 续链**合并包**；禁拆两轮、禁「请说开 γ」 |
| 仅缺用户 Unity 操作/日志 | **请你补测**（Agent 已先查 Editor.log 仍不够时） | **no**（停人测） | 不新开 Step；勿默认要长粘贴；本质仍是 `await_human` |

「根因已钉死」最低标准（须同时）：
可观察失败现象一句 + 至少一条可复现 Console/审计关键词 + 与物理口径/当前窗假设的对应关系一句。
否则一律按「未钉死」→ 推荐只读排查。

「异现象」最低标准（须同时）：Discover 白话结论与本窗当前 A#/目标句对**同一复现局**所要收敛的结果不一致（例：窗要满管压差收敛，日志钉的是微液塞穿气）。仅换审计关键词/门控函数名不算异现象。与 §1.1「同一现象」互补：异现象 → 挂起另开，不算本窗止损续烧。

### 0.4 拍板 / Auto 代选

- **非 Auto**，或 `auto_follow: no` / 硬停：推荐写明后，**必须**等用户回复再派策划/程序员。用户说「准」→ 采用【推荐】；交接记「用户采纳推荐」；**禁止**再要求复读「开 γ」。
- **Auto**且 `auto_follow: yes` 且未硬停：同条代选【推荐】并派岗/执行；交接**必须**留据一行：`Auto采纳推荐：{项}（未等人确认 · 未命中硬停）`。缺留据 → 视同违规静默代选。
- 自动跟之后的实现 Step **仍须** Exit Gate 待验；不得攒批跳测。

### 0.5 规格漂移闸门（强制 · 2026-07-16）

Discover 推翻或大幅修正此前的根因假设 / 现象描述（即「规格漂移」）时：

1. **先改口径，再改码**：必须先更新 `物理口径.md`（或对应 A# 验收条款），使其反映新的根因认识，才能开下一 Step / 热修的 Mandatory Code Changes。
2. **禁止**只在交接口头提一句「其实是 XX 问题」就直接写代码补丁，把新认识留在对话里、不落盘——下一个 Agent 读物理口径仍是旧判断，会重复踩坑。
3. 口径变更须与旧口径显式区分：标注换层（α→β/β→γ）或在 `物理口径.md` 追加一行「修订记录：日期 + 原判断 + 新判断 + 触发证据」。
4. 方案审 / CR 发现 Mandatory 隐含的根因假设与 `物理口径.md` 当前文本不一致 → **blocker**。

判定「是否漂移」的最低标准：本轮 Discover 结论与上一版物理口径对**同一现象的根因归因**不同（不是仅换关键词/换函数名）。仅换审计关键词、门控函数名不算漂移，不触发本闸门。
长期任务感知的资源/漂移信号见 [long-task.md](./long-task.md)；不另造 fuse 数字。

### 0.8 Discover 全路径预扫（强制 · 2026-07-28）

触发：Discover 阶段拟写 Mandatory 含门闸/放行/改道类改动；或 Mandatory 触及下列**信号枚举**任一项。

#### 「跳」定义（钉死）

**「跳」** = 拟修复路径上的**门闸/调用边**（函数 → 下一门禁 / 早 return / 放行点），**不是** `codegraph_explore` 返回结果条数。CG 命中条数多 **≠** 已扫 ≥2 跳。

#### 信号枚举（最低集 · 方案审机械检）

触及任一项 → Mandatory 须含 Discover 预扫链（见下）：

| 大类 | 最低集（须列名或等价可检索句） |
| --- | --- |
| 放行/拦截 | 放行、早 return |
| 命名模式 | `allow_*` |
| 路由/交接 | `redirect`、`handover` |
| 就绪/注册 | Ready、Register |
| 未就绪门闸 | `*_not_ready`、`upstream_not_ready`、`terminal_not_ready` |
| 通路改道 | 增改通路改道 |

#### 正文扩写点名（须高于最低集 · 防漏判）

§0.8 正文或 Mandatory 须**显式点名**下列模式（可归入上表大类，但**不得**只用大类代替点名）：

- **`ShouldBypass*`**（`allow_*` 大类**不代替**本项点名）
- **`force*`** / **`suppress*`**
- **`TryAdvance*`** 中「改用另一条路径」模式

方案审：Mandatory 触及上表最低集却缺扩写点名句 → **major**；缺预扫链 → **blocker**。

#### 预扫链（强制）

1. **覆盖范围**：沿拟修复路径从入口到目标出口，列**扫过的符号**（`path:symbol`）；不得只扫入口函数一层。
2. **CG 预扫**：须 `codegraph_explore`（或 CRG 等价窄查）覆盖路径上 **≥2 跳**（门闸/调用边）。
3. **读码复核**：CG 已覆盖 ≥2 跳后，**无论 CG 是否命中**，对拟改入口读码复核 **≥1 跳**；若 CG 未覆盖某跳 → Mandatory 须写「CG 未覆盖 → 已读码 `path:symbol`」。
4. **多门闸一次策略**：路径上 **≥2 个门闸**时，Mandatory 须写**一次**放行/改道策略（合取/互斥/顺序），禁拆成「先试第一道、失败再开第二道」。
5. **BMAD 自包含**：预扫结论、扫过符号、策略句须在 Mandatory / Discover 落盘段自包含；禁只留对话、不落 `未完成.md`。
6. **禁止只开第一道门**：不得仅放宽/打开路径上第一道门闸，等 Verify 失败再开第二道；须一次策略覆盖 ≥2 门闸（见 lessons：suppressStreak/legacy · 预扫 ≥2 跳）。

缺预扫链 / 缺扫过符号 / 缺读码回退 / 只开第一道门 → 方案审 **blocker**；缺扩写点名 → **major**。

## 1. 诊断止损线（强制）

### 1.1 什么叫「同一现象」（计数口径 · 钉死）

以 **用户白话目标** 为准，不以 A# / H# / Console 新关键词自动换编号。

| 算同一现象（计数连续） | 允许清零 / 另起计数 |
| --- | --- |
| 同一复现场景下，用户要的结果不变（例：「加压后液体应进收集端、压差应收敛、不要对打震荡」） | 物理口径 **换层**（明示 α→β / β→γ）且用户确认新边界 |
| 仅换日志关键词、换门控函数名、换「热修#N」 | **禁止**宣称「新切片」清零止损 |
| 热修短窗上的 Verify 失败（见 §2.1） | 热修失败计入该主现象累计 |

主窗 `未完成.md` 须写一行：`止损计数：主现象「…」= x/3（含热修失败 y 次）`。

### 1.2 触发

同一现象下，下列事件合计达到 **3** 次则 **强制停车**：

- 主窗：证据推翻初判 → 新增 Step / 改写主修假设
- 热修：该主现象下热修短窗 Unity/Verify **失败**（§2.1）

则：

1. 禁止继续写主窗 Step N+1，**禁止**再开热修 N+1，**禁止**同 A# 交审级再修。
2. 【推荐】**A#/口径复议**（§0.7）：回物理口径 / 验收条款重定界（可新开短窗或修订 `物理口径.md`/A#）。
3. PM 白话说明「命中止损线 → 须复议 A#」；确认包等人「准」后再开下一窗；黑板记「触顶 → A# 复议」。同包**提示**可选「完整碰撞」（未点名不跑，见 §0.7）。

### 1.3 与旧「热修不计」的关系

**废止**「热修旁路短窗一律不计入主窗 3 次」的无上限说法。
热修仍可不占主窗 Step 序号，但 **失败次数计入同一现象止损**（§2.1）。

### 1.4 止损 0→1 路径完整性（强制 · 2026-07-28）

触发：同一主现象（§1.1）下止损计数由 **0→1**——首次「证据推翻初判 → 新增 Step / 改写主修假设」，或该主现象下热修 Verify **失败计 1 次**（见 §1.2 / §2.1）。

下一刀（新开 Step / 热修 Mandatory / 同现象交审级再修）前，Discover 或 Mandatory 须含**点名反思句**，回答：

> **为什么上一轮不是最后一门？**

最低标准（须同时）：

1. **点名至少 1 个**具体门闸/调用边（`path:symbol` 或可检索函数/门闸点名），说明上一轮为何未覆盖、未放行或未打到该点。
2. 与 §0.8 衔接：若路径上仍有 **≥2 门闸**，须说明本轮策略如何**一次**覆盖（禁重复「只开第一道门」）。

**空话判据**（方案审 **major**）：仅写「已考虑路径」「已全面分析」「上一轮未完全解决」等不可证伪句，**未点名**具体门闸/调用边。

缺反思句 / 空话 → 方案审 **major**；主窗未写止损计数行仍开下一刀 → **blocker**（与 §1.1 主窗行联动）。

本窗方案审核档位已因文件/机器热度升到 L3 或双轮 CR，且同现象止损计数变为 ≥1（**热度爆炸**）→ 下一刀确认包**提示**可选完整碰撞（与 [collision-review.md](./collision-review.md) 用途分级「提示」同句）。单纯 heat≥medium 的首次方案审不提示。未点名不跑，不替代 §1.4 反思句。

## 2. 热修旁路（强制）

下列改动 **默认不得**并入已 ≥5 个未完成/诊断 Step 的主 Full 长窗：

- 构链误杀、预检过严、日志/marker 口径
- 单点门控、纯诊断开关、命名修正
- 与主现象无关的旁路 bug

默认：`Express`（仅注释/日志，机械）或 **Direct**（行为小改热修——对话内切片，不落盘）或 **Standard 短窗**（独立 `{方案短名}-热修-短标题/`，仅 `未完成.md`）。
主窗只留一行交叉引用。用户/TL 显式要求并入主窗除外。

### 2.1 热修失败上限（强制 · 计入止损）

同一主现象（§1.1）下：

| 条件 | 动作 |
| --- | --- |
| 热修短窗连续 Verify 失败 **≥2** | 下一次默认推荐 **必须**为 A#/口径复议（止损重定界）；**禁止**推荐热修 N+1 |
| 该主现象下热修失败累计 **≥3**（含非连续） | **等同命中 §1 止损线** |
| 热修目标已达成、残留属另一白话目标 | 本热修窗停写；残留回主窗 Discover（**不**自动开下一热修） |

热修窗须写：`本主现象热修失败累计：k`（与主窗止损行对齐）。

热修被判定「失败已放弃」（命中本节任一条）后，**同条**按 [doc-windowing.md](./doc-windowing.md) §热修/切片失败或回退即封存 收口（归档或标 `archived`），不得留悬空「未完成」。

### 2.2 放行类热修合取条件（强制）

若 Mandatory 含「放宽拦截 / `return false` 放行 / allow_* 早放行」类改动：

- 必须写清 **合取条件**（至少 2 项可证伪，例：fill 区间 ∧ 气压 S>C ∧ 链就绪/收集端已有液…）。
- **禁止**仅「tube==某端容器即放行」或「任意 fill 放行」而无上界/下界。
- 触及 `物理口径.md` 硬句（如「整链够满才进收集」）→ Mandatory 须引用该条款；方案审缺合取或缺引用 → **blocker**。

### 2.3 热修改执行面时的并行实现一句（强制）

热修若改 PhaseGraph / path transfer / ValveFSM / legacy 任一执行面门控：

- Mandatory 须 **一句**：本路径与另一路径如何互斥 / 降级 / 复用同一 helper。
- 只打补丁、不写该句 → 不得 `implementation-ready`（方案审 **blocker**）。
- 与 §3 主窗并行实现收敛同时生效；热修不得以「短窗」为由跳过。

## 3. 并行实现收敛闸门（强制）

若同一用户可见行为同时存在 **≥2 条执行链**（典型：PhaseGraph + legacy / 路径传递 + 域求解）：

1. 任一收敛切片（含物理口径 α/β/γ）的定版条件须含：
   **本轮保留哪条、另一条如何降级/删除/门控**。
2. 只打补丁、不写收敛完成定义 → 方案审 **blocker**，不得 `implementation-ready`。
3. 「并行实现长期并存」须 TL 明文批准并写入 `未完成.md` 硬约束，否则按未收敛处理。
4. 热修短窗适用 §2.3，不得整段躲开本闸门。

---

## 4. 结案即封存（强制）

- 主现象已迁到 `物理口径.md` + 切片 α/β/γ 后：旧长文只进 `已完成/`，**禁止**再往旧单文件或历史全文末尾追加 Step。
- β/γ、并行热修、未签收旁路（如 A24）→ **新开短窗或并行文件夹**，不挤进当前 α 窗。
- 整案 `completed` 后：`未完成.md` 改为「无活跃 Step」短页或删除活跃 Mandatory，仅保留索引链接。
- **迁夹硬项**：终态（签收 / 失败 / 回退 / 空闲离执行中）→ **同条** `migrate-pipeline-window.ps1`（或同等）；只改状态不搬家 = **未结案**（见 [handoff-automation.md](./handoff-automation.md) §E、[doc-windowing.md](./doc-windowing.md) §迁移动作）。
