# 先原型后定案（prototype）

> 触发：方案阶段遇到状态机 / 数据形状 / UI 设计问题，纸上难推、需运行验证时自动加载；策划经 [planner/SKILL.md](../planner/SKILL.md) §2.9 指针引用。
> 出处：mattpocock/skills prototype（2026-08-07 对照落地，本地化为 Unity 语境，不引入 Web 工具链）。
> 原则：原型是**回答问题的临时代码**，问题决定形状；一次性产物遵守工作区卫生（`.ai-gates/tmp/` 或 OS tmp，不入正式窗口）。

## 选分支

先明确要回答的问题（从用户原话、周围代码判断，或用户在场时直接问）：

| 问题 | 分支 |
| --- | --- |
| 「这套逻辑 / 状态机 / 数据形状对吗？」 | **LOGIC**：纯逻辑可运行演示 |
| 「这界面应该长什么样？」 | **UI**：场景内变体切换或走查清单 |

- **LOGIC 分支（Unity 本地化）**：纯逻辑可运行演示——脚本 / 场景驱动，含 free-play（任意顺序点动作）+ 引导走查（场景化步骤），非开发者也能驱动；核心逻辑写成可复用纯逻辑，可搬回真实代码。
- **UI 分支（Unity 本地化）**：场景内变体切换或走查清单；变体须结构上 **radically different**（不同布局 / 信息层级 / 主操作），禁仅配色 / 文案差异。
- 问题含糊且用户不可达：按周围代码默认（后端模块→LOGIC，界面/组件→UI），原型顶部写明假设。

## 6 条通用规则

1. **throwaway 从第一天并明示**：命名含 `prototype`，放靠近将被使用处；沿用项目既有结构，不新建顶层形态。
2. **可运行零思考**：一条命令 / 一个入口即可启动，无需阅读说明。
3. **无持久化默认**：状态驻内存；持久化是被测问题而非依赖。
4. **跳过打磨**：无测试、无抽象、最小错误处理；目的是快速学到东西。
5. **每动作 surface state**：逻辑每次动作后输出完整相关状态；UI 每次变体切换后渲染，让变化可见。
6. **完成后决策折回真实代码**：验证过的决策折回实现；原型本身留 **primary source** 分支（不进 main），并在实现 Step / 窗口文档（或派发工件）记录分支指针；main 只留验证过的决策。

## 反模式

- 写测试——原型要测试就不再是原型
- 接真实持久化——除非问题就是持久化
- 泛化——「以后可能支持 X」不属于原型
- 逻辑与演示壳混写——纯逻辑保持可搬回
- 框架 / 打包依赖
- 演示外壳 / 临时 UI 外壳进生产——原型约束下写的代码折回时重写
