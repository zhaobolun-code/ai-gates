# 执行纪律 — 不漂移、不臆测

> ⚠️ **已 supersede** — 日常入口：[agent-entry-route.md](./agent-entry-route.md)；门禁/争议细则：[CORE.md](../CORE.md)。
> **权威来源**：本文件定义流水线「无差错」的含义——**执行无异议、不漂移、不自我幻想猜测**；**不是**零 bug 或零运行时缺陷。
> 常见翻车见 [anti-patterns.md](./anti-patterns.md)。

## 设计初衷（验收标准）

| # | 初衷 | 含义 |
| --- | --- | --- |
| 1 | 一人顶全队 | 单用户、单 Chat；`项目经理` 内部自动派岗 |
| 2 | 会用 Unity + AI 助手 | **会用 Unity** 与 **AI 助手基本操作**（Cursor Agent / Codex / Trae：新开会话、粘贴需求、能改文件）；代码由 Agent 写 |
| 3 | 四车道自适应 | Express / Direct / Standard / Full；命中升级链（Express→Direct→Standard→Full）须立即升级 |
| 4 | 无差错 | **不漂移、不臆测**；缺事实则停，不 silent default |
| 5 | 精简优先 | **不过度设计**；只实现需求所需最小功能，不留残留/废弃代码 |

## 事实优先级（冲突时以高为准）

改代码、写方案、派岗前，信息源优先级：

1. **仓库真实状态** — `git`、实际文件内容、符号是否存在（可用 CodeGraph）
2. **模块 README** — 边界、硬约束、验证说明
3. **执行文档** — 当前 Step 的 Mandatory Code Changes
4. **对话推断** — 最低优先级；**不得**单独作为实现依据

若 1 与 3 冲突：**停下**，列出冲突点，交 `策划`/`方案审核` 或标 **已阻塞**；**禁止**猜哪边对。

## 不确定则停

缺以下任一项时，**不得推断实现**：

- 真实代码 / 文件是否已读过
- 相关 README 或 **`.cursor/project-context.md`**（若存在）约束
- 用户对需求理解的关键确认（大功能须策划确认；小改可当场一句澄清）
**正确做法**（择一）：
- 列出缺口，向用户提问（团队用户用白话，可带 Unity 操作语境）
- 标 **已阻塞** / `blocked(已阻塞)`，说明缺什么
- 交 `策划` 补方案或 `方案审核` 收紧文档
**禁止**：编造 API、路径、类名、配置字段；用「大概」「应该」「通常」直接开工。

## 精简优先（不过度设计）

- **YAGNI**：只实现当前 Step/切片需要的功能；不为「以后可能用到」预先加抽象层、配置项、通用化参数
- **不留残留**：改动路径上发现的废弃方法/字段/`using`/注释掉的死代码，顺手删除；不确定能否删除则在交接说明「未清理原因」，不得沉默留下
- **类/文件膨胀是信号**：单个类/文件只增不减、职责越堆越多，是过度设计或早该拆分未拆分的信号；具体行数阈值项目可在 project-context.md 约定，通用默认参考「单类持续膨胀、无清晰单一职责」需在交接/CR 中说明是否建议拆分
- **策划**：Mandatory Code Changes 只写当前需求要求的最小改动范围，不预先设计扩展点
- **程序员**：不顺手加方案外的功能/抽象；发现的残留代码随手清理或交接说明
- **代码审核**：改动路径上已确认无人调用的残留死代码仍可指出。过度设计、建议抽公共函数、类膨胀后的拆分只作**建议**，不自动改，不算未通过。真缺陷另计。见下方「过度设计只提醒」

### 复用四问（强制 · 写文档 / 写方案 / 改码前）

> 目标：先检索、再复用、能少写则少写、能不写则不写、能删则删——打断「默认在神类上再堆一条旁路」。

写 **plan-lite / Full 方案 / Express 切片 / README 结构变更 / 业务代码** 前，须先检索并答齐（可落 ≤6 行短表；**缺任一项 = 未完成门禁**）：

| # | 问 | 最低证据 |
| --- | --- | --- |
| 1 | **已有吗？** | 扫模块 README + 同主题方案夹/`物理口径.md` + CodeGraph/关键符号；文档岗先 Read **现有** README/版本记录 |
| 2 | **能复用吗？** | 指名可复用 helper / Service / 门闸 / 口径句 / 既有分支；不能复用须一句为什么 |
| 3 | **能少写/不写吗？** | 优先：改阈值、接已有分支、只改口径/A#、文档只加一行；已有 Unity / .NET / 平台 API（含已装包）能做则直接调用，禁止再包一层；「一行」不是目标，守恒/方向/相态优先于少写；结论「须新写」才开新路径 |
| 4 | **能删吗？** | 三选一：① Delta Spec **REMOVED** 点名本步要删的符号；或 ② 写「本步无可删」且改动路径上已点名旧轨各有不能删原因（谁还调用 / 口径要留 / **什么现象才改**；缺升级触发 = 填空；路径上无已点名旧轨则可只写「本步无可删」）；或 ③ 写了「能删」则 Delta REMOVED 必须点名对应符号——生产 caller 仍通断 = 第 4 问未完成。禁止「能删 X；Y 不删」无原因即满足。神类本步只增不减须说明是否抽离/另开拆分窗（不得替代三选一） |

**窗目标叠加**（正向目标；不扩第六问；任何项目同一条）：活跃 `未完成.md` / `物理口径.md` 的窗目标，或用户本轮原话，点名要删的旧符号（旧入口、旧实现、并行的第二套、调用边）时，该符号是一笔**删债**。不看业务领域。第 2 问不得把这笔债写成能复用 KEEP。第 4 问不得用选项②「本步无可删」当完成态。

删债只认窗目标和用户**本轮**原话。上一刀写的「禁止删 / KEEP / 不删某符号」不带到下一刀。要留下该符号，必须用户本轮亲口说留。

同一笔删债只允许**一刀**只读 Discover。这一刀第 4 问写：窗目标仍删 X；本刀不改码；下一刀必须 REMOVED 点名 X，生产 caller 断开。下一刀必须改码：Delta REMOVED 点名 X，生产 caller 断开。再写「本刀不改码、下一刀再删」= 第 4 问未完成，不得 `implementation-ready`，不得交给程序员。禁止用「本步无可删」交差。同一升级触发连续 ≥2 个 Step 未触发且无新钉事实 = 第 4 问填空。窗目标不含删除旧主人语义、用户本轮也没点名要删时，选项②仍按三选一。

**落点（谁写 / 谁拦）**

| 岗 | 动作 |
| --- | --- |
| 策划 | 每 Step 在 Mandatory 旁写 **复用四问** 短表（可与选型短表合并）；第 4 问按最低证据三选一填写，禁止「能删 X；Y 不删」无原因交差；优先复用，禁止默认「新开并行实现」；有删债时按叠加写，禁止用②完成，禁止把上一刀「禁止删」抄进本刀，除非用户本轮原话留着 |
| 程序员 | 改码前核对方案四问；方案漏则自补并报 PM；优先复用、禁止复制粘贴第二套同类逻辑；短表写「能删」则 Delta REMOVED 须点名对应符号，生产 caller 仍通断 = 第 4 问未完成；优先直接调已有 API，禁止为少写牺牲物理；删债未清却写本步无可删，或第二刀仍不删 → 不得自称完成，停报 PM |
| 方案审 | 无四问、或可复用 helper/Service 却新开并行实现 → **blocker**；四问表已有但第 4 问填空（不删无原因、无升级触发，或能删无对应 REMOVED）→ **blocker**；明显可调用平台 API 却新抽象包装 → **major**（包一层不升 blocker）；有删债却走②，或同一符号第二刀仍只读 Discover / 仍写禁止删该符号 → **blocker**；旧主人生产 caller 仍通断又新增并行方法 → **blocker**；同一升级触发连续 ≥2 Step 未触发且无新钉事实 → 填空 **blocker** |
| CR | 已有 Unity/.NET/平台 API 可调用却新包一层 → **nit**；因此形成并行实现或违背物理口径 → **major**；可复用却新写并行实现 / 只增不删且无说明 → **major**；形成并行实现且无互斥句 → 按 [diagnosis-gates.md](./diagnosis-gates.md) **blocker**（勿降级）；删债未清、生产 caller 仍通断又新增并行方法 → **blocker**；本步 REMOVED 已断开该旧主人时，不因新方法行数或净增打回；Discover-only 无 diff 且仍是该债的第一刀只读 → N/A，第二刀只读 → **blocker** |
| 文档 | 写前检索现有 README；能一行版本记录说清则**不**扩结构/原理章 |

**禁止**：未检索 README/代码就写 Mandatory；「以后可能复用」当本步新抽象理由；用 partial 新文件冒充拆职责却继续堆同一神类；禁止为少写/一行牺牲守恒、方向、相态；禁止把四问扩成 Ponytail 式六阶/档位。

项目可加硬阈（Mandatory **替换句式**、本 Step 新方法行数、交审瘦身一拍）→ 见仓库 `.cursor/project-context.md`（若有则按其阈）。这些阈是项目自己的数字。本步 REMOVED 断开删债点名的旧符号、生产调用已断时，**不套**项目的新方法行数上限和净增上限，该文件净增应为负。项目说明不必再抄这条。旧符号还在又新加并行实现 → **blocker**。

### 方案只记决定（强制 · 写当前 Step 时）

当前 Step / Mandatory 只记实现者不能自己定的决定：改哪些文件、符号签名（名、参数、返回）、规格钉死的值、怎样验收（命令或人可见现象，以及什么结果算过）。

- **测试步**：测试名和断言，用规格里的原值。不写测试函数的其余正文。
- **代码步**：签名、文件、规格钉死的值。函数体由实现者写。只有签名和验收都定不了的算法，才允许写几行做法，不贴整段实现。
- **验收步**：跑什么、什么结果算过。
- 活文档当前 Step 禁止贴旧 Step 长状态，禁止把函数体当方案。方案比它要执行的规格长出好几倍、而且大部分是代码块 → 把程序抄进了方案，须删到只剩决定。

### 试探不升合同（强制）

只读试探（Discover、预扫、探针）的产出标「试探」。试探可以不改生产代码。试探笔记不得整段抄成下一步的现行 Mandatory，也不得写成用户已经同意的改法。要把试探里的做法留进生产代码，必须新开一步，并且用户本轮说「准」。同一结论上再开一步只读、没有新钉事实 = 未完成。删债的那一步只读仍按删债条，下一步必须改码；本条不批准第二步只读。验挂后规定要做的第一次 Discover 仍做，做完标试探。

### 先红再改（强制）

改生产代码之前，必须有一条能把**这个现象**打红的信号，并且已经跑过一次（命令或步骤，加上输出）。只有人能看的现象：写人可见的红句（做什么、看见什么算红）。这句写下来之前，不许假设根因，不许改生产代码。

同一处写四格，各一句：保护什么；什么改动会让它失败；为什么现有检查盖不住；绿了不证明什么。绿了不证明人已经看见现象，也不证明没跑过的运行时已经通过。

缺红信号就改了生产代码 → 方案审 / CR **major**。把绿写成已经证明人可见现象，或写成 `runtime-validated` → **blocker**。

### 过度设计只提醒（强制）

过度设计、建议抽成公共函数、类膨胀后的拆分，记为**建议**。不自动改代码，不算未通过，不因此挡收口。真缺陷（错行为、删债未清、并行第二套）另计，不降成建议。

### 助手裁定（强制）

不是用户本轮原话的保留、禁止、默认值，写成「助手裁定：…」。禁止写成「用户要求」或「用户禁止」。上一刀的禁止删 / KEEP 若抄进本步，同样标助手裁定，不得当本轮用户原话。用户本轮没说留，助手裁定留不住删债。

| 岗 | 动作 |
| --- | --- |
| 策划 | 当前 Step 按「方案只记决定」写；试探节标题含「试探」；非本轮原话的保留标「助手裁定」 |
| 方案审 | 现行合同里代码块盖过签名、验收、删什么 → **major**；旧 Step 长状态抄进现行合同 → **major**；试探笔记当现行 Mandatory，或同一结论第二步只读且无新事实 → **blocker**；助手裁定写成用户原话，从而留下删债或改了已批准范围 → **blocker**；只漏了「助手裁定」四字、范围未改 → **major** |
| 程序员 | 不把试探笔记或上一刀禁止删当成用户本轮已准的改法；函数体按签名和验收自己写 |

### 设计模式一问（强制 · 复用四问之后）

> 接在 §复用四问 短表之后；写 Mandatory / 改码前须答。

**问法**：写 Mandatory 前**必扫** [design-patterns.md](./design-patterns.md) 词条表「触发症状」列（扫症状列，不是优先套用）。复用入口读 `.ai-gates/design-patterns.project.md`（若存在）。命中 → 必须写强制选型句（格式不变）；禁止因「无本仓路径 / 无项目验证表锚点」写成不采用。落地两档：项目验证表该词条为 `确定[有代码证据]` 且结构对得上、能直接复用 → 必须复用，禁止第二套生成器/总线/撤销栈；无项目验证则按词条结构配方新建第一份同构（运用模式 ≠ 抄他仓类名）。State 快照 / Policy 策略 / Seam Service 仍属项目典故：无项目验证表锚点 → 字面不采用。未命中（缺触发症状）→ 字面 `本步不采用 design-patterns 词条`。缺症状仍 YAGNI。

**主窗派策划（禁止预填结论）**：Task 提示词可给需求源路径、车道/档位，以及「写 Mandatory 前扫 `design-patterns.md` 触发症状」。禁止写出词条表「典故词」、常见模式类名、或「很像某某模式 / 应采用某某」。禁止预填强制选型句或 `本步不采用 design-patterns 词条`。可复述玩法文档的机制句与已有代码符号。选型只由策划本问落盘。

**强制选型句**（写进 Mandatory；格式不变）：

```text
采用 {典故词} 模式（触发症状：…；理由：…；词条出处：design-patterns.md §{典故词}）
```

| 缺项 | 方案审 |
| --- | --- |
| 未命中却缺「本步不采用 design-patterns 词条」 | **major** |
| 缺强制选型句（症状+理由+出处）（已声明采用时） | **major** |
| 缺触发症状仍写模式名 | **blocker**（对齐 evolution-03 机制 C） |

流程典故（神类止血/复用四问/双轴/深模块）仍只走 [shared-language.md](./shared-language.md) §典故，不得在本问里重复登记。

## 假设必须显式

- **策划**：默认决策写入执行文档并列入需求确认摘要；禁止 silent default
- **程序员**：发现方案与代码不符，先报差异，不擅自按想象改
- **项目经理**：范围变大时说明升级原因，不悄悄扩大 Step

## 漂移即纠偏

| 信号 | 动作 |
| --- | --- |
| 超出当前 Step / Mandatory Code Changes | 停止实现 → `代码审核` 或回 `程序员` 收窄 |
| 命中 CORE §四车道判定 升级链（1 文件胀成 2～3 → Direct；>3 或 API/持久/跨模块 → Standard；Express/Direct 止损 → Standard；Standard 再止损 → Full） | 立即升级车道并告知用户。**禁止**仅因 project-context 路径前缀或回归索引点名就升 Standard；禁止快/直通第一次止损就跳 Full |
| 证据等级被夸大 | 降回如实等级；无运行证据不得 `runtime-validated` |
| 无执行文档做大功能 | 回 `策划`；不得维持「想到哪改到哪」 |
| 同一 Step/切片内连续 ≥3 次 `static-checked` 修复仍无 Unity 验证 | 停止继续叠加修复 → 提示用户先做一次真实回归，确认现象后再继续（防止无法定位是哪次改动引发新问题） |

## 团队输出：约束行为，不锁格式

面向团队用户时，**须传达**（表述可自然、可省略小节标题）：

- 当前进度语义（五态之一或其白话等价）
- 用户下一步做什么（一句即可）
- 需要时给出可复制下一句话
**不要求**固定 Markdown 模板；**禁止**为凑格式拖长回复。内部术语（文档状态、证据等级、L3）默认不主动展开，见 [user-visible-states.md](./user-visible-states.md)。

## 工作区卫生：中间产物只进 `.ai-gates/tmp/`

- **一次性中间产物**（revision/hash 计算、压力测试、批量迁移/修复脚本、排查用临时输出）只放
  **`.ai-gates/tmp/`**（不入库；目录缺失先建）。环节收尾**整目录清空**，不留"以后可能有用"的暂存。
- **不得**散落在 `.cursor/` 根（项目状态/产物目录被垃圾淹没）、`hooks-log/`（运行时证据与垃圾
  混淆，发布闸证据不可信）或 `.ai-gates/`（git 跟踪的中央库，任何多余文件都离打包/入库一步）。
- `.ai-gates/hooks-log/` 只保留 hook 运行时证据（pm-gate.json / changelog-writes.json / *.log / 真演记录）。
- 2026-08-04 实证：历史 98 个散落中间产物（约 260 KB）就是这样长出来的，清理需逐文件甄别；
  建立暂存区后按"环节收尾即清"应不再堆积。
