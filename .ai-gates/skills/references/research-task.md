# research 子代理任务（可选 · 外部事实调研）

> 触发：主窗遇到「需要一手资料 / API 事实 / 官方文档核实」且值得开子窗时；纯问答仍主窗直接答。
> 出处：mattpocock/skills research（后台子代理 + 引用 Markdown），2026-08-07 对照落地。

## 何时用

- 需要核实 API 签名 / 官方文档 / 版本行为 / 授权与许可事实；
- 阅读量大、可离线交付给子窗的背景调研；
- 方案 / CR 需要「证据引用」但主窗不想占上下文。

## 派发要点

- 任务随 spawn **初始消息**投递（本机 fork_turns=none 投递不可靠 → 见 [model-routing.md](./model-routing.md) §子窗健康检查与有界等待）；
- 明确：**只读调研，禁止改业务代码 / 交付物**；产物只写指定文件（`证据/research-{主题}.md` 或 `.ai-gates/tmp/`）；
- 限时：30 分钟内无进展 → 主窗接管。

## 产物

- Markdown 一份：结论先行 ≤5 行 → 证据清单（来源 URL / 文档节 / API 名 + 原文摘录）→ 未核实项显式列出；
- 证据分级：官方一手（API 文档 / 源码）> 官方博客 > 社区可信；**禁止无出处断言**；
- 引用格式：`[来源] <URL|文档路径> · <摘录>`；未核实项写 `待核实`，不得冒充已核实。

## 与流程的关系

- 调研结论可进方案「链接」或 `证据/`；不直接定车道 / 方案（决策仍归方案审 + 确认包）；
- 禁止把 research 当验收：调研通过 ≠ 业务 A# 通过。
