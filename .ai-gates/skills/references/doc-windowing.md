# 文档窗口化（方案文件夹 + 未完成/已完成）







> 权威：本文件。降 token：审核默认只读「未完成」窗口，禁读「已完成」归档全文。  



> 路径总规则 → [doc-path-defaults.md](./doc-path-defaults.md)。  



> 止损/热修/并行实现/结案 → [diagnosis-gates.md](./diagnosis-gates.md)。







## 目标







1. **一方案一文件夹**，文件名固定，避免单文件滚成 1000+ 行史书。  



2. **进行中与已完成拆开**：日常实现/审核只读未完成窗口。  



3. **物理口径**可单独短文件，执行文档只链不抄。  



4. **当前 Mandatory 必须可独立打开**，禁止「实现时去历史全文里翻 Step N」。







## 目录与命名（强制）







用户未指定路径时：根目录 = **project-context 覆盖**（若有）> 通用 `.ai-gates/Doc/`（见 [doc-path-defaults.md](./doc-path-defaults.md)）。  



本仓库 Chemical 未指定时根为：`Assets/LabSDK/.../化学文档/压力系统/`。







```text



{文档根}/{方案短名}/



  未完成.md                 ← 默认可读（活跃窗口）



  Mandatory-Step{NN}.md     ← 可选；当前 Step 的 Mandatory 全文（默认可读）



  已完成/                   ← 默认禁读全文



    _索引.md



    Step01-短标题.md



    历史全文-窗口化前.md    ← 迁移档案；抽出 Mandatory 后禁止再读



  物理口径.md               ← 可选；默认可读



  证据/                     ← 可选；默认禁读



    YYYYMMDD-摘要.md



```







| 名称 | 规则 |



| --- | --- |



| `未完成.md` | 固定名；只含当前未完成内容 |



| `Mandatory-Step{NN}.md` | 当前 Step Mandatory **须**落在方案根或完整写入 `未完成.md`；**不得**仅存在于历史全文 |



| `已完成/` | 已签收 Step / 长证据；默认禁读全文 |



| `物理口径.md` | 现象层 SoT；执行窗只链不抄 |



| `证据/` | 长日志外置；主窗一行摘要 |







用户指定路径时：仍以用户路径为根，但须用同一套文件名。







## 状态分类夹（强制 · 文档根下）







> 方案夹**本身不加**「签收-」「失败-」等前缀；用文档根下的**状态分类夹**收纳。  



> 状态变化时：**同条收口**创建（若不存在）对应分类夹，并把整个方案文件夹（含 `.meta`）迁入；再改交叉路径。







```text
{文档根}/
  执行中/                   ← 活跃：开窗 / 改码 / 待测 / 诊断中未放弃（禁止停放空闲）
    {方案短名}/
  签收/                     ← 用户验收结案；或空闲枢纽（无活跃 Mandatory / 无可改码窗）
  失败/                     ← Verify FAIL 放弃、止损冻结、热修链止损（含原「止损」）
  回退/                     ← 代码/方案已 reverted
  停写/                     ← 本窗停写、口径不适用（未判失败、亦未结案）
  换层/                     ← superseded，主诉改挂他窗
```

> **空闲枢纽（策划/方案审可机械引用）**：无活跃 Mandatory、无可改码窗、非待测、非诊断中的空闲枢纽**不得**长期停 `执行中/` → 同条迁 **签收/**（续作再迁回执行中或新开短窗）或 **停写/**；占位空壳禁止新开于 `执行中/`。见 anti-patterns §方案与文档状态「空闲枢纽」行。







### 状态 → 分类夹







| 触发（文档状态 / 判定） | 迁入 |



| --- | --- |



| 判定 **Direct**（无落盘、不建夹） | **无夹可迁**；升 Standard 后按 Standard 规则（落盘时才建夹） |
| 新建短窗 / 进行中主题枢纽 / `draft`～`in-progress` / `implementation-ready` / `step-completed`（**待 Unity**）/ `blocked`（诊断中未放弃） | **执行中** |



| 用户签收结案、`completed`；或枢纽/主窗 **空闲**（无活跃 Mandatory、无可改码窗、非待测、非诊断中） | **签收** |



| Unity/验收 FAIL 且放弃本窗；止损触顶冻结；热修链止损停工 | **失败** |



| 明确回退代码/方案（`reverted`） | **回退** |



| 停写但非失败（换层前停笔、口径不适用） | **停写** |



| `superseded` / 主诉改挂 | **换层**（若仅停写不改挂 → **停写**） |







**合并约定**：不再单独建「止损」分类夹；止损冻结与失败放弃一律进 **失败**。







### 迁移动作（同条强制）







1. 若目标分类夹不存在 → **创建**（Unity 项目一并补 folder `.meta`）。  



2. `Move` 整个 `{方案短名}/` + 同名 `.meta`（保留 GUID）。  



3. 更新主窗 / 物理口径 / README / 邻窗相对路径（分类夹多一层时 `../` → `../../`）。  



4. 方案夹内自指「方案文件夹」绝对/仓库相对路径同步改写。  



5. **禁止**只改 `未完成.md` 状态字段却不搬家；**禁止**用文件夹名前缀代替分类夹。

6. **必须**调用 `migrate-pipeline-window.ps1 -DocFolder … -ToCategory …`（Move + 改写「方案文件夹」+ `repair-doc-crosslinks.ps1 -Path … -Apply`）；**禁止**手挪方案夹后只改状态字段/漏改链。勿把 Move 塞进 `update-doc-state`。歧义短名不自动改，人工确认。

**结案检查单硬项**：状态进入终态（`completed` / 签收结案 / 失败·止损放弃 / 回退 / 空闲枢纽须离 `执行中/`）→ **同条必须**完成本节搬家；未跑 migrate（或同等）仍停 `执行中/` → **未结案**，PM/程序员不得宣称收口。权威接线 → [handoff-automation.md](./handoff-automation.md) §E。







### 谁负责







| 角色 | 责任 |



| --- | --- |



| **PM** | 判状态变更后派发「迁入哪一类」；收口轮检查分类夹与指针一致；**空闲未迁签收 = 未收口** |



| **策划** | 新建 Standard/Full 默认落在 `{文档根}/执行中/{方案短名}/` |



| **程序员** | 结案/回退/失败收口时若本轮改文档状态 → 同条完成搬家（或交 PM 同条做完） |







进行中主题枢纽（含仅挂物理口径但仍会续作）放 **执行中/**，与进行中短窗同级。  
**空闲须迁签收**：无活跃 Mandatory、无可改码窗、且非待测/非诊断中 → 同条迁 **签收/**；禁止空闲长期停 `执行中/`。  
续作下一 Step：迁回 **执行中/**，或新开短窗于 `执行中/`。  
仅临时停笔、未结案 → **停写/**（非失败）。  
legacy 单文件：已完成归档 → **签收/**（可保持单文件）；未完成 → 窗口化后进 **执行中/{方案短名}/**。







历史单文件长方案：下次统筹必须拆入本结构。拆分前审核须标明可读章节，不得默认全文。







## `未完成.md` 应含什么（上限思维）







1. **给下一个 AI 的第一条指令**（须与「文档状态」一致，见 §首段指令）  



2. 目标（≤3 行）+ 硬约束（只列本次）  



3. 链接：物理口径、`Mandatory-Step*.md`（若有）、README、`已完成/_索引.md`  



4. 上一步摘要（≤30 行；**禁止**整段 Console）  



5. 当前 Step 摘要 + A#；Mandatory 可外置文件  



6. 文档状态（**仅允许** [state-machine.md](./state-machine.md) 表内状态；禁止自造 `verify-failed` 等）  



7. 止损计数一行（若适用，见 [diagnosis-gates.md](./diagnosis-gates.md) §1.1）  

**软上限：150 行。** 超过时须在文档状态写明超限原因与压缩时点，并优先把已完成 Step、历史解释、长证据迁入 `已完成/` / `证据/`，或将当前 Mandatory 外置到 `Mandatory-Step{NN}.md`。超150且无外置说明 → 方案审至少 `major`；为压行删除 A#、当前 Mandatory、止损/状态真相 → `blocker`。







**禁止**在 `未完成.md` 保留已完成 Step 长正文；**禁止**要求读者打开 `历史全文-*`。







## 首段指令 = 真相源（强制）







「给下一个 AI 的第一条指令」与「文档状态」**必须同条一致**：







| 文档状态 | 首段须写明 |



| --- | --- |



| `implementation-ready` | 已过一轮确认或等「准」；确认后同条开始改码（禁再要口令门） |



| `in-progress` | 正在实现当前 Step |



| `step-completed` | **禁止再改码**；待 Unity / 等用户测 |



| `blocked` | 等 PM Discover 决策；禁止未选就开始改码 |



| `completed` | 无活跃实现；勿改码 |







Verify 失败 / CR 收口 / 开始改码后：**同条改写首段**。首段仍写 `in-progress` 而状态已是 `blocked`/`step-completed` → 方案审/CR **major**（故意不改 → **blocker**）。







口语别名仅可出现在括号说明（例：`blocked`（Unity 未过））；**状态字段本身**仍用表内枚举。







## Discover / 排查上限（强制）







- 主窗「Discover / 只读排查」正文合计 **≤15 行**（含补测改判）。  



- 超出 → 整段迁 `证据/YYYYMMDD-*.md`，主窗只留 **一行结论 + 路径**。  



- 禁止把多轮 Console 深挖堆进 `未完成.md` 变成迷你历史全文。







## 证据外置（强制）







- Unity 长日志 / 大截图说明 → `证据/YYYYMMDD-摘要.md`  



- `未完成.md` / 交接 **只留一行**结论 + 路径  



- 对话默认禁止粘贴 >40 行 Console







## 完成即迁移







1. Step 正文 → `已完成/Step{NN}-短标题.md`  



2. 更新 `_索引.md`（**当前活跃**一行必须指向真实活跃 Mandatory/未完成）  



3. `未完成.md` ≤30 行摘要替换；删或归档旧 `Mandatory-Step*.md`  



4. 禁止主窗与归档双写  







## 热修/切片失败或回退即封存（强制 · 2026-07-16 · 2026-07-17 补状态分类夹）







热修短窗或切片被判定「失败已放弃」（触发 [diagnosis-gates.md](./diagnosis-gates.md) §1/§2.1 止损，或用户/PM 决定改路径放弃当前短窗）后，**收口当轮同条**完成下列，不得留悬空态：







1. **状态分类夹**：整夹迁入 `{文档根}/失败/`（回退则进 `回退/`）；见上节「状态分类夹」。  



2. **窗内归档（可选）**：体量大时另将过程摘要迁本夹 `已完成/{短窗名}-failed.md`；父窗/主窗 `未完成.md` 补一行指针到新路径。  



3. **原位标记（仅极小窗）**：不值得整夹迁移时，在其 `未完成.md` 首段标 `archived`（原因 + 去向），并仍须把所在方案夹迁入对应分类夹（或并入父窗归档）。







**同时**：主窗止损计数行（diagnosis-gates.md §1.1）须同条更新，与该次失败对齐。







**两个方向都要防**（对应 skill-eval-checklist.md 滥用反例 C5b/C5c）：







- **禁止过度归档**：仍在诊断中、根因未钉死、尚未判定失败的短窗，**不得**抢先迁出「执行中」或标 `archived`——只有触发止损或用户/PM 明确放弃才迁入「失败」。



- **禁止拖延归档**：已明确判定失败/放弃的短窗，**不得**长期留在「执行中」或根下冒充可改码窗。







方案审 / CR 发现短窗已被主窗弃用却仍在「执行中」/根下且未标 `archived` → **major**。







## 新案形态（强制）与 legacy 单文件







- **新建** Standard / Full 执行方案：**必须**用本文件夹结构；**禁止**再新建「单文件滚历史」长方案当模板。  



- Express：默认不落盘、不建窗（Chat 切片）；如需落盘仍走 `未完成.md`（现状保留）。  



- 既有单文件执行方案（无 `未完成/` 结构）：文首加一行  



  `> **形态**：legacy 单文件（窗口化前）；**勿当新案模板**；新 Step 优先拆窗或只读指定章节。`  



  不强制立刻迁移旧文。







## 无窗车道（Direct 强制）

- **Direct 不建方案夹**：不生成 `未完成.md` / plan-lite / Full 文档；策划产出（A#/切片）只在主窗对话，仓库零落盘（tmp 落盘也算落盘，禁止）。
- 跨会话 / 换窗 / 改不完 → **自动升 Standard 并落盘**（此时才按本文件建夹）。
- Express 默认不落盘、不建窗（Chat 切片）；如需落盘仍走 `未完成.md`（现状保留）——与「新案形态」/「与 Express」节同句统一（m1）。
- 状态迁移：Direct 无夹可迁；升 Standard 落盘后按「状态分类夹」表 Standard 规则。

## 新窗齐套标记（kit · 强制）

- 标记：方案夹根 `.kit-v1`，单行 `kit=v1 name={短名} created={YYYY-MM-DD}`。
- 有 `.kit-v1` → **强制**同目录 `物理口径.md`；无标记历史夹**不强制**回填。
- 新建用 `new-pipeline-window.ps1` 一次生成齐套（含 `.kit-v1`）；`.kit-v1` 为唯一齐套强制信号。

## 活跃可改码窗登记（强制倾向）







同一文档主题下若存在 **≥2** 个可改码窗口（主窗 + 热修等）：







- 主窗 `未完成.md`（或 project-context 短表）须有一行：  



  `当前唯一可改码窗：{相对路径}｜其余冻结`  



- 程序员只改登记窗；要换窗须 PM 改写该行。  



- 未登记却并行改两窗 → CR **major**。  







## 审核读权限（强制 · 降 token）







| 读者 | 默认可读 | 默认禁读 | 例外 |



| --- | --- | --- | --- |



| 策划 | `未完成.md`、`物理口径.md`、`Mandatory-Step*.md`、代码入口 | `已完成/**` 全文、`证据/**` 全文、历史全文 | `_索引` + **一个**指定已完成 Step；**点名一个** `证据/_…派发.md`（见下） |



| 方案审 / L3 | 同上 + 派发白名单 | 同上 | 同上；**点名一个**派发工件 |



| 程序员 | 同上 + Mandatory 源码（**优先 CodeGraph**） | 历史全文、无关长方案、整目录扫读 | 仅当 Mandatory 文件缺失时记 blocker，不得改去读历史全文；可点名一个代码审核派发工件 |



| CR / 对抗 | 派发最短包 | 同上 | `_索引`+一个 Step；**先读点名 `_…派发.md`** 再读其白名单 |



| Subagent | **仅**派发白名单（含点名派发工件） | 其余一切 | 无 |

**复核派发工件例外（精确）**：允许 Read **派发时明确点名的一个** `证据/_方案审核派发.md` / `_Step{NN}-代码审核派发.md` / `_Step{NN}-对抗CR派发.md` / `_Step{NN}-验收派发.md`。禁止扫描 `证据/`、读取同目录其它文件。细则 → [review-dispatch-lifecycle.md](./review-dispatch-lifecycle.md)。

**修复黑板例外（精确）**：测挂后修复 / 交审级再修 / CR 复审时，允许 Read **点名的** `证据/_repair-blackboard.md`（可与上一条派发工件同轮各点名一个）。禁止借此扫 `证据/` 其它文件。模板 → [repair-blackboard.md](../templates/repair-blackboard.md)；规则 → [diagnosis-gates.md](./diagnosis-gates.md) §0.6。

**待准经验例外（精确）**：可晋升时允许 Read/Write **点名的** `证据/_lesson-pending.md`（可与派发工件/修复黑板同轮各点名一个）。禁止借此扫 `证据/` 其它文件。模板 → [lesson-pending.md](../templates/lesson-pending.md)；规则 → [lessons-learned.md](./lessons-learned.md) §准全自动。

**知识缺口例外（精确）**：不确定分级入队 / PM 确认包清队时，允许 Read/Write **点名的** `证据/_knowledge-gap.md`（可与上列例外同轮各点名一个）。禁止借此扫 `证据/` 其它文件。模板 → [knowledge-gap.md](../templates/knowledge-gap.md)；规则 → [knowledge-gap.md](./knowledge-gap.md)。







**封死例外**：一旦存在 `Mandatory-Step{NN}.md`（或 Mandatory 已完整写入 `未完成.md`），Read `历史全文-*` → **major**；故意重复 → **blocker**。







任意一轮「做/审当前 Step」默认可读文档合计宜 **≤ ~300 行** + Mandatory 源码；又读进第二份 1000+ 行长文 → 本轮记 major，按白名单重派。







## 隔离派发最短包（强制）

```text
默认可读：

- {文档根}/{方案短名}/物理口径.md   （若存在）



- {文档根}/{方案短名}/Mandatory-Step{NN}.md  （若存在）



- [Mandatory 源码路径…]



- 上轮 blocker 摘要（≤20 行，可选）



禁止：



- 已完成/ 下除 _索引 外的全文；证据/

```







禁止向 Subagent 粘贴主对话实现讨论或整份旧方案。







## CodeGraph 定向（强制倾向）







程序员 / CR：先 `codegraph_explore` 当前符号与调用链，再按需 Read；**禁止**「为谨慎把 PressureManager 全目录读一遍」。  



**禁止**因 soft budget /「额度已用尽」话术整轮弃用 CodeGraph——见 [codegraph-probe.md](./codegraph-probe.md)。图谱不可用时在 findings 声明，并只 Read Mandatory 列出的文件。







## 输出上限（强制倾向）







交接 / findings 默认短表：改了什么、A#、怎么测、blocker 列表。  



长推理与大段代码块不默认贴进主对话（用户或 CR 点名再展开）。







## 与 Express







Express 默认不落盘、不建窗（Chat 切片）；如需落盘仍走 `{文档根}/{短名}/未完成.md`（现状保留）。通常无 `已完成/`。







## 禁止







- 往单文件末尾无限追加已完成 Step  



- 新建 Standard/Full 仍用无窗口的单文件长方案当主形态  



- 审核「为了保险」读全方案文件夹  



- Mandatory 只活在历史全文里  



- 把物理口径长文复制进 `未完成.md`
