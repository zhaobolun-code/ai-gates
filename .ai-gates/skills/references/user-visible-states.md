# 用户可见状态（团队表述）

> **权威映射表**：Agent 面向团队用户时，用下表 **5 态** 作为进度**语义**；内部状态机仍以 [state-machine.md](./state-machine.md) 为准。
> 团队用户入口：[USER-GUIDE.md](../../USER-GUIDE.md) · 输出纪律：[execution-discipline.md](./execution-discipline.md)

## 五态定义

| 用户可见状态 | 一句话 | 用户动作 |
| --- | --- | --- |
| **进行中** | Agent 正在写方案、实现或内部审核 | 等待或按 Agent 提示回复 |
| **待你确认** | 大功能开工前需确认理解 | 回复理解是否正确 |
| **待 Unity 测试** | 改动已完成，需运行验收 | 在 Editor 测试并回复通过/不通过 |
| **已定版** | 验收通过或 Express 小改 / Direct 对话内切片已认可 | 无（或生成周报） |
| **已阻塞** | 必须先解决某问题 | 按 Agent 说明或联系 TL |

## 内部状态 → 用户可见（映射）

| 内部文档状态 / 环节 | 用户可见状态 |
| --- | --- |
| `draft(草稿)` / `review-pending(待审核)` / 策划撰写中 | **进行中** |
| 策划「需求确认」等待用户回复 | **待你确认** |
| `implementation-ready(可实现)` / `in-progress(实现中)` / 代码审核进行中 | **进行中** |
| `step-completed(步骤完成)` / 等待 Unity 回归 | **待 Unity 测试** |
| `runtime-validated(运行已验证)` / `completed(已归档)` | **已定版** |
| `blocked(已阻塞)` | **已阻塞** |
| Express 车道改完，用户已口头认可 | **已定版** |
| Express 车道改完，尚未确认 | **待 Unity 测试** 或 **进行中**（目视即可时 Agent 说明） |
| Direct 对话内切片完成、用户口头认可 | **已定版**（无归档） |
| Direct 改完未确认 | **待 Unity 测试** 或 **进行中**（目视即可时 Agent 说明） |

## 用户语言（强制）

对话里的白话（「你下一步」、确认包、五态说法、周报正文）和**落盘正文**（方案夹里的段落、A#、口径句子；不含文件名）跟**本会话用户语言**。

- 中文会话：中文正文，专名可夹英文（Express、A#、`PM`）。
- 英文会话：英文白话与英文落盘正文；禁止把确认包 / 「你下一步」/ 方案段落写成中文。口令仍认 `准` = `approve`。
- **文件名不改**：`未完成.md` / `物理口径.md` 等仍是机器锚。对英文用户说话时用英文说法，不必念中文文件名。
- 不是两份 Skill；不是文件名别名表。Skill 源码、钩子日志、校验脚本输出不在本条范围。

## Agent 输出要求（项目经理统筹时）

面向团队用户（默认：用户仅粘贴「项目经理 + 需求」，或未要求进阶/TL 模式）时：

**机器层**：回复**必须含**字面 `[PM]` YAML（给 hooks）；不对团队讲解 `review_tier` 等字段名。120 分钟窗口是近似门禁，不是「本条已判定」。

**用户可见**（权威 → [CORE.md](../CORE.md) §用户可见输出）：Express 简略轮只输出白话 **「你下一步」**（不要摘要表）；非 Express = 白话摘要表 + **「你下一步」** 与五态语义。

**约束行为，不锁格式** — 用自然语言即可，**须传达**：

1. **进度语义**：对应五态之一（可说「等你 Unity 里测一下」，不必写「用户可见状态：」标题）
2. **用户下一步**：一句白话；Express 简略轮须含车道理由、下一岗、五态、用户动作（见 CORE §Express 简略）
3. **需要时**：给出可复制下一句话（L1.5 等：**提示**新开 Chat 粘贴派发块；不校验用户是否新开）
**不要求**固定 Markdown 小节；**禁止**为凑版式拖长回复。

内部字段（文档状态、证据等级、blocker 分级）仅在用户追问、TL 模式或维护场景展开。

**禁止**在面向团队用户时，单独抛出 `implementation-ready`、`hard blocker`、`L3` 等术语而不翻译。

**待你确认**（强制）：每个决策点只发 **1** 条确认包（开始改码 / 续链合并 / Verify 选型）；「准」同条自动干完；细则 → [demand-clarification.md](./demand-clarification.md) + [handoff-automation.md](./handoff-automation.md) §0。

**多选决策**（强制）：列出 A/B 选项时，必须同时写 **【推荐】** + **【为什么】**（及一句不选推荐的后果）；禁止只甩选项让用户裸选；此即该决策点的唯一一轮。

用户回复「测试通过」且证据足够时，Agent 内部迁 `runtime-validated` / 标 **已定版**，**不要求用户改执行文档**。  
若物理链仍有明确下一窗 → **同条**发续链**合并包**（开窗+本步方案+开始改码）；**禁止**「请说开 γ」，**禁止**再拆改码确认轮。

## TL / 进阶用户

用户明确说「Full 车道」「完整流程」「L3」或身份为 TL 维护流程时，可同时输出内部状态与 §hard-soft-blocker，见 [CORE.md](../CORE.md) 与 [evidence-levels.md](./evidence-levels.md)。
