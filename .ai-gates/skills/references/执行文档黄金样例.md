## 分阶段实现计划

### Step(步骤) 1: 对齐 onlyImportantLogs 默认值

Goal:

- 开发环境默认 `onlyImportantLogs=true`（或项目等价字段）且与 README 一致。

Prerequisites:

- 无

Requirements:

- 不删除现有 Debug API。
- 不改变非 Debug 路径的执行顺序。

Pitfalls:

- 不得把 `[HealthCheck]` 等关键标记误门控掉。

Mandatory Code Changes:

1. 修改 `[path/to/module]/[EntryFile].{cs|ts|py|go}`（或 README 指定的等价入口）:
   - 将 `onlyImportantLogs` 默认值改为 `true`。
   - 若存在序列化/配置字段，确认覆盖行为并文档化。
2. 集成验证：
   - 必需日志：`[ModuleName][Init] action=debug_gate result=ok onlyImportant=true reason=align_readme`
   - 失败处理：编译/类型检查失败则 blocker，不猜测 API。

Required Validation Logs Or Signals:

```text
[ModuleName][Init] action=debug_gate result=ok onlyImportant=true reason=align_readme
```

Regression Validation:

- 场景：启动含该模块的最小可运行环境（Editor / dev server / 单测夹具），运行 ≥5 秒或执行一次主流程。
- 预期结果：关键健康类日志仍可见；冗余 Debug 被门控。
- 通过标准：Console/日志截图或用户口头确认。
- 若失败，收集：过滤后日志、`onlyImportantLogs` 实际值。
