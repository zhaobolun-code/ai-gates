# 代码审核双轴模式（规范轴 + 规格轴）

> 触发：CR 时「按规范查」与「按规格查」结论可能互相污染（如：越出 A# 却符合语言规范）。Standard **L1.5+**（含 L1.5 / L2）与 **Full 主 CR**：**默认** `axis: standards+spec`；findings 必须分组 `[规格轴]` / `[规范轴]`。L1 仍可选用本模式（不把默认写进 L1）。Direct 普通档：保持单表，**不**默认双轴。Express：不变（不启用本模式）。
> 出处：mattpocock/skills code-review（Standards + Spec 并行子代理），2026-08-07 对照落地。与既有对抗模式并列，**不替代**。

## 双轴定义

| 轴 | 查什么 | 判据 |
| --- | --- | --- |
| 规范轴（standards） | 与仓库规范的一致性：CORE / 岗位 SKILL、模块 README 硬约束、语言维（C#/Lua）、复用四问、神类止血（若有） | 是否符合「应当怎么写」 |
| 规格轴（spec） | 与本次规格的一致性：A# 覆盖且未越界、Mandatory / Delta Spec 落实、DO NOT TOUCH 未碰、回归场景仍覆盖 | 是否符合「这次要做什么」 |

## 运行方式

- 默认：**一个子代理内按轴分开扫**，结论分开列，最后合并 findings——保证「越界但合规」与「在界内但不规范」两类问题都显式出现。
- 并行（可选）：改动面大或 PM 指定时，两个子代理各扫一轴，互不读对方结论；合并时若同一条目两轴结论冲突（如规格要求删、规范要求留）→ 交 PM 定夺，不自行折中。
- 禁止：把规范轴的风格偏好当规格轴 blocker；用「符合规范」掩盖越界（越界仍是 blocker）。L1.5+ 规范轴可点名 5～6 条 Fowler 气味（神秘命名、重复、散弹手术、投机抽象、基本类型偏执、特性依恋）。**永远是判断**；不得单独当规格轴 blocker。仓库已有规则优先。不抄满 Fowler。Direct 不默认双轴、Express 不变。

## 输出

findings 短表按轴分组：`[规范轴]` / `[规格轴]` 前缀；集成维照常必扫。双轴一致无 blocker → 按 [handoff-automation.md](./handoff-automation.md) §C 收口。
