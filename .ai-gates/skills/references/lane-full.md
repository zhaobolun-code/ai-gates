# Full

写给人看的话之前先读 [human-voice.md](./human-voice.md)。它不占参考文件的两份名额。命令、路径、表头、周报骨架不改口吻。

1. 开方案和热修扫错题大纲。问句和点名改法不扫。命中写日期或关键词一行。
2. 先读 `full-lane-decision-tree.md` 和 CORE 的 Full 强制条。这张卡不复述那份清单。
3. 方案夹、方案审、一次「准」、程序员子窗、隔离代码审，停点与 Standard 卡相同。CR 默认隔离；Subagent 不可用或失败时按 [isolated-review.md](./isolated-review.md) 降级并标「非独立 CR」。
4. 业务 C# 没有代码图也没有 CodeGraph，代码审不收口。
5. 没测过不许写通过。只有隔离审核子窗能写 `hooks-log/cr-stamp.json`；缺戳不得标「隔离复核已完成」。若按规则降级为非独立 CR，可如实记录并继续，不得冒称隔离完成。含业务 `.cs` / `.lua` 且还要人测时，运行 `scripts/set-knife-state.ps1`。

不因为文件次数改用这张卡。用户确认「建议完整流程」或点名完整流程，这一刀才用。

要读代码或长文档、要搜索仓库、要跑终端、要看日志，先打开 `read-evidence`、`run-evidence`、`log-evidence` 里对应的一份，再派子窗。主动搜索排除 `.ai-gates/tmp/`，已经点名的路径仍可读。派发只写岗位、轮次、派发文件路径。不贴哈希、预期哈希、blocker 原文、岗位卡。子窗交回只留三行。实现子窗自己读岗位卡。隔离审核子窗不读常驻卡，只读派发白名单。主窗不改两份派发文件。

同一方案夹，且口径、选型、A# 相对上一刀没变：不派方案审，派发写 `campaign: yes` 和上一刀 Step 号。两步及以上、文件不相交、没有 depends-on：同一回复里一起派。有依赖或抢同一文件才一个接一个派。禁止续问同一个子窗。再查就新派。细则在 `circuit-windows.md`，用到才打开。
