# ai-gates

用 AI 改项目，常卡在一句「做好了」。旧配置还能不能读？改动到底测过没有？问它，回答有时含糊。还有幻觉：它会写出项目里根本不存在的函数、文件或接口，说得却像已经接上了。

ai-gates 是装在项目里的一道护栏。你用平时的话提需求。恰好一个业务文件，只改注释、已有日志或不超过 3 行的常量，而且不改变行为，它可以直接改。会动到存档、接口，或者牵出好几个模块，它先写方案；该审的先审，你回「准」才改代码。改完再由另一边看。测试没跑，就写没跑，不能写成通过。适合还要长期改的项目。临时写个脚本，用不上。

做完要写清查到哪一步：没运行、只做了静态检查、还是运行过。连续两轮只有静态检查、没有实际运行，会在这里停一下，先补一次真正跑过的验证。

## 举个例子

给配置加热重载，同时还要兼容旧配置。这种不会直接动文件。它会先写清楚改哪些文件、旧配置怎么兼容、怎样验证。该审的先审。你回「准」之后，它才改代码。

改完再换一个视角看，尽量不靠刚才的实现过程和自说自话。然后告诉你哪些测试实际跑了、哪些没跑。配置文件能不能被你的项目读出来，还是得你自己打开看。

只改一行注释，而且符合上面那种小改，就不必走这些步骤。

## 安装

把下面整段贴到 Cursor、Codex 或者 Claude Code。它会先说要改哪些文件，你同意了才动手。

### 贴给 Agent（推荐）

```text
请把 ai-gates（AI 开发流水线技能包）从 https://github.com/zhaobolun-code/ai-gates 安装到当前项目，替代手动下载和解压。初始化不在这一步完成：
- 取最新 release tag，克隆/下载到临时目录；校验根目录有 .ai-gates/ 且 skills/VERSION 是合法 x.y.z 并等于该 tag，不符就停下。
- 把临时 .ai-gates/ 的 skills/hooks/scripts/rules/codex、根文档、hooks.json、link-platform.*、LICENSE 复制到项目根 .ai-gates/；若已装过，先比对版本，仅更新时替换，保留 project-context、mcp.json、hooks-log、tmp、verify、regression-*、pipeline-* 等项目状态。
- 运行 link-platform.ps1 建传送门，写 install-info.json。macOS / Linux 若用 link-platform.sh，只用于建传送门，不是整套一键安装。机器拦截仍要 PowerShell 7，登记命令名仍是 powershell。
- 运行 pm-init.ps1，只生成 .cursor/project-context.md 等说明文件，不代替我选模型，不要说已经可以开工。回归索引可后补。
- 完成后报告版本与传送门状态，请我先说「项目经理 检查健康」。项目说明和模型等我说「项目经理 初始化」。
动手前先列计划等我确认；失败或网络问题不要改文件，给出手动下载方案。
```

### 另外两种

- Windows 上一条命令：`powershell -ExecutionPolicy Bypass -c "irm https://raw.githubusercontent.com/zhaobolun-code/ai-gates/main/.ai-gates/scripts/install-ai-gates.ps1 | iex"`
- 从 [Releases](https://github.com/zhaobolun-code/ai-gates/releases/latest) 下压缩包，解压到项目根（包里就是 `.ai-gates/`）。

官方 Cursor 市场还没上架，先别从市场装。Mac 和 Linux 没有整套一键安装。`.sh` 只用来建传送门。

## 装完怎么用

安装到这里为止：文件在，传送门（各软件的入口文件）建过，安装信息写下了。先说「项目经理 检查健康」，看钩子（自动拦截）接上没有。

初始化是下一步。你说「项目经理 初始化」，它才问高档和低档各用哪个模型，并请你确认项目说明。贴上面那段时，脚本只会把说明文件建出来，不会替你选模型。回归索引可以后补，不填也能开工。

以后用「项目经理」加上你要做的事。方案你回「准」。它叫你试的时候，自己打开看。

升级说「项目经理 升级 ai-gates」。

| 你说 | 也可以说 | 做什么 |
| --- | --- | --- |
| 项目经理 | PM | 加上需求，开始一件事 |
| 准 | approve | 同意这个方案，或同意记下来 |
| 初始化 | init | 第一次把项目说明填上 |
| 检查健康 | doctor | 看入口文件和拦截接上没有 |
| 升级 | upgrade | 把这套护栏更新到新版本 |

## 各家软件拦不拦得住

Windows 用系统自带的 PowerShell。Mac 和 Linux 要另装 PowerShell 7，命令叫 `pwsh`。只有 `pwsh`、没有 `powershell` 时，拦截不会启动，检查健康会报错，不算装好。两个都没有，就只剩对话里的规则。

| 你用的 | 实际情况 |
| --- | --- |
| Cursor | 能拦。有没有接上，看检查健康 |
| Codex 命令行 | 能拦。有没有接上，看检查健康 |
| Codex 桌面 | `apply_patch` 可能绕过拦截，不能指望所有写入都被拦住 |
| Claude Code | 能拦。有没有接上，看检查健康 |
| Trae | 没有自动拦截，规则还在 |

检查健康看的是入口文件和拦截接上没有。机器放行是另一件事：只说明这轮对话在两小时里打过开工标记，不说明这一条已经做完判定，更不说明这次改动审过或验收过。命令认不出、状态文件读坏时，这道检查会放过。拦截不是绝对边界。被拦住以后怎么办，写在[使用指南](./USER-GUIDE.md)里。

## 它按改动选松紧

判定就是这次改动走哪一档。它主要防四种情况：没判定就改，没测就说通过，小改走了全套，同一错换个皮再来。

| 档 | 什么时候 | 例如 |
| --- | --- | --- |
| Express | 恰好一个业务文件，只改注释、已有日志或不超过 3 行的常量，不改变行为 | 改一行注释 |
| Direct | 默认。普通的行为修改，或两到三个文件，不碰接口、存档、跨模块 | 给函数补一条校验 |
| Standard | 超过三个文件，或涉及接口、存档、跨模块、范围说不清。前两档第一次反复失败，也会升到这里 | 配置热重载，同时兼容旧配置 |
| Full | 命中更严的强制条件 | 按 CORE 判定，不在这里概括 |

判完只读其中一张说明。

## 记在这个项目里

做错了记进错题本。测试没过先留下记录，修好后由你确认，才写入这个项目。以后写方案会先看相关的错题。再碰到类似的地方，审查会更严。

做成并且验过的做法，可以起一个短名字，记进典故（已验证做法）。以后提到这个名字，约定和适用边界一起回来，不必每次重讲。比如「一错不二犯」，指的是坑和结构分开记。

两本默认留在当前项目。回「准」只是同意写进这里，不会自动上传。你另说「上传」，才交给公开的收集处。维护者合并之后，别的项目才能用「项目经理 升级 ai-gates」拉回来。窗号和路径不跟着走。

## 看整张图

文件夹一多，人和助手都容易只盯着眼前这一件。迷雾地图按项目里的工作文档来画：已经建立工作文件夹的才上图，关系够才连线；只在文档里提过、还没建工作文件夹的，显示成雾。普通资料目录不会因此都进图。

它是这些工作之间的导航，不是代码索引。具体内容仍回到原来的文档。助手会问要不要画、要不要更新，你同意才做。完成后双击 `.ai-gates/verify/fog-map.html` 就能看，不用另开网页服务。特别小的改动可以不建文件夹，图上也就没有那一块。别的目录里的旧图不算。

## 想多查一层

可以让两路助手互相找洞，从「怎样算失败」往回看设计断没断，或者同一轮写两种看法再对照。默认不做。得你开口，也更费时间和钱。日常还是普通检查。
