# ai-gates

**AI 几秒就能改出一堆坏代码。正因为如此才要 gates：你用母语提需求，流程交给流水线，降低认知负担。关键节点须人测试通过。**

这套技能从三层一起改 AI 辅助编程：vibe coding 保住手感并收得了尾；自进化让失败变成规则；外源性元认知是对未知的探索。

你只管vibe，ai-gates来coding。

## Vibe coding

心流：不纠结语法、不翻文档、不预设完整架构，像画画一样凭感觉把代码构建出来。ai-gates 用你几乎感觉不到的护栏让你勇敢向前，vibe 从玩具变成工具。

- **交付闭环**：每个需求一个文件夹；结束后从「执行中」挪到「已签收」。回「准」= 理解 + 方案 + 开工一次确认，每个节点也可以改方案。做完能收尾。
- **止损闭环**：同一做法反复失败就停下来换路，把「此路不通」记进错题本。以后再改这块容易出问题的地方，检查会自动加严（热度）。
- **四车道 + 任务路由**：按改动大小自动选流程——小改几步就完，大改会先写方案再检查，文件变多或跨模块当场加严，你不用自己选。策划和写代码可以配普通大模型，检查和验收可以配更强的模型。大约少用 70% 的模型用量，好钢用在刀刃上。

传统 vibe 卸掉认知负担之后，同时也卸掉了质量、债务、依赖，小改变成雪崩。gates 把过关标准、停点和关键节点的人测留在流程里。

## 灰箱

你不用每天去读流程说明书，但也不用两眼一抹黑。平时助手只告诉你下一步做什么，你同意了再动手，做到该你试的时候你自己试——省事，但不是瞎干。等你想看看这些事怎么连在一起、哪块还没人做，再打开迷雾地图。很小的改动可以不建新文件夹，地图上也就不会多一块。

- **为什么要有迷雾地图**：事情一多，光靠点文件夹看不出「这件事跟哪件有关、接下来该做哪件」。助手也常常只盯着眼前那一个文件夹。这张图把已经有的工作文件夹画成一块块地：有文件夹才上图，关系够才连线；只提过名字、还没建文件夹的，画成雾。空着的地方本身就说明还有事没做。
- **为什么好用**：连线和空白一眼能看见，不用把几十个文件夹挨个打开。图是根据现有文档自动画的，你不用再维护另一份说明。只有你点头才画；有文件夹也不会自己偷偷画一张。要看细节仍去原来的文档，图只是总览。
- **打开**：助手问过、你同意之后再生成，然后双击 `.ai-gates/verify/fog-map.html`。直接打开这个文件就行，不要另开网页服务。别的目录里如果还有一份旧图，那份不算。

## 自进化

做错了有记录，做成了也有记录，下次还能用。

- **错题闭环**：测试没过会先记下；修好后问你准不准写进本项目的错题本；下次写方案会先看；同类问题再出现时检查会更严。目的是同一错不再犯。
- **会生长**：做成了、办法也验过了，就写进「典故」——一个短名字，以后一提，助手就想起整套约定。先留在本项目；要给大家都用，先改成不带本项目名字和路径的说法，再说「上传」。收进技能包之后，你说「项目经理 升级 ai-gates」，别的仓库才能用上。



## 元认知（进阶尝试）

有几项进阶检查不在常规流程内，通过选择启用：让两路助手互相找漏洞、从「怎样算失败」往回看设计有没有断、同一轮写出两种看法再对照。已经试过几次（能挖到问题和断点，也更费时间和费用）。日常仍走普通检查。这是技能对未知的探索，不是装上就会自己反思。

## 30 秒安装，3 分钟熟练

方式 A 把安装交给一段粘贴。装好之后日常：提需求、回「准」、按提示在关键节点验收。

### 方式 A（推荐 · 零手动 · 全平台同一段）

把下面这段**整段**粘贴给 Agent；它会联网取最新版、装库、建好连接并引导初始化：

```text
请把 ai-gates（AI 开发流水线技能包）从 https://github.com/zhaobolun-code/ai-gates 安装到当前项目，替代手动下载、解压和初始化：
- 取最新 release tag，克隆/下载到临时目录；校验根目录有 .ai-gates/ 且 skills/VERSION 是合法 x.y.z 并等于该 tag，不符就停下。
- 把临时 .ai-gates/ 的 skills/hooks/scripts/rules/codex、根文档、hooks.json、link-platform.*、LICENSE 复制到项目根 .ai-gates/；若已装过，先比对版本，仅更新时替换，保留 project-context、mcp.json、hooks-log、tmp、verify、regression-*、pipeline-* 等项目状态。
- 运行 link-platform.ps1（Unix 用 .sh）建传送门，写 install-info.json。
- 运行 pm-init.ps1；说「项目经理 初始化」即可开工（回归索引可后补），生成 .cursor/project-context.md。
- 完成后报告版本与传送门状态，并告诉我以后用「项目经理 + 需求」入口。
动手前先列计划等我确认；失败或网络问题不要改文件，给出手动下载方案。
```
