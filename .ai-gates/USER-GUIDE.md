# 使用指南 — 30 秒安装，3 分钟熟练

> 版本：以 [VERSION](skills/VERSION) 为准（入口不写死版本号）
> 第一次接触：README（30 秒安装）→ 本文（3 分钟熟练）→ 需要时再扫 [METHODOLOGY.md](./METHODOLOGY.md)（为什么这么设计、真实数据；**不是**万能药）。  
> 新仓库还没配置？先说 **`项目经理 初始化`**，再提需求。

## 你只需要记住一件事

在任一能改文件的 AI 会话里（Cursor 选 Agent 模式；Codex / Trae 同理），粘贴：

```text
项目经理
[描述你要什么 / 遇到什么现象 / 贴报错或截图]
```

也可简写为 `PM`（**`项目经理` = `PM`**）。

**新项目第一次**还可：

```text
项目经理 初始化
```

（**`初始化` = `init`**，故 `PM init` 等组合效果相同。）

升级技能包：`项目经理 升级 ai-gates`（**`升级` = `upgrade`**，`PM upgrade ai-gates`）。  
体检：`项目经理 检查健康`（**`检查健康` = `doctor`**，`PM doctor`）。

不用记各种角色名。助手会用白话告诉你下一步。需要你确认方案、以及测一测时，**仍要你回复**。助手用你说话的语言回复；方案里写的说明也是同一种语言（中文里可以夹 Express、`PM` 这类词）。文件夹名字可能仍是中文，不用管。你说没看懂，助手会用同样白话重讲，不用新口令。

> 即使你知道该写代码，也请从「项目经理 + 需求」开始，否则容易漏步骤。

## 第一次接入

在助手里粘贴 `项目经理 初始化`。助手会生成项目说明、对齐传送门；技术栈由它探测后请你确认。回归索引（必测场景）可后补——不填也能 `项目经理 + 需求` 开工，填了热度升档更准。CodeGraph 可选，须你同意再装。

完整命令与排查 → [tl-onboarding.md](skills/references/tl-onboarding.md)  
**前提**：用能改文件的 Agent 模式（Cursor / Codex / Trae 同理）；要验业务现象时，通常要能在编辑器里跑起来（例如 Unity 点 Play）。

## 对你意味着什么

- **你要做的**：README「你只需要做三件事」——提需求、回「准」（=`approve`）、按提示验收。  
- **语言**：助手跟你说话、写方案说明，都用你这一会话的语言；文件夹文件名可以仍是中文。  
- **你不用做的**：自己改一堆流程文档、自己挪文件夹、背很多角色名。  
- **它自动做的**：机器能验的（编译错误、回归模块冒烟、证据归集）会自动验并留下证据——但「通过了」这最后一句仍要你说。  
- **它会生长**：全世界使用者一起让技能进化。AI 每犯一个错都是进化契机：它可能问要不要留下这次的教训或结构；你回「准」才进本项目表。要把条目交给大家，另说「上传」。换项目升级，才能用上已经长好的部分。不是自动改规则。  
- **它不会做的**：不测就保证已经修好；把别人项目里的路径和测试清单直接拿走就好用。

## 基本操作

| 你想… | 怎么做 |
| --- | --- |
| 提需求 | 对话里发「项目经理 + 需求」（`项目经理`=`PM`） |
| 确认可以做 / 留下错题或典故 | 回「准」（=`approve`）。「准」不等于传到网上 |
| 把本项目典故/错题交给大家 | 另说「上传」（公开收集仓：开分支交 PR 即可，合并须权限；本机须已登录 GitHub 命令行；未登录只留本机队列） |
| 收下全世界已经长好的技能 | 说 `项目经理 升级 ai-gates` |
| 让它能改文件 | 模式选 Agent，不要选只读 |
| 单独再审一轮 | 它提示时，新开一个对话，粘贴它给的文字 |
| 在 Unity 里测 | 点播放 → 按步骤操作 → 看控制台 → 停播放 → 回复通过/不通过 |
| 跑自动化测试（TDD 单测） | 仓库根有 `Tests/EditMode/` 时：项目根 PowerShell 跑 `powershell -ExecutionPolicy Bypass -File .ai-gates/scripts/run-dotnet-editmode-tests.ps1`（trx 判定：total≥70 且 failed=0 方绿；秒级、不占 Unity） |
| 它说本步不用开编辑器 | 看它给的核对结论，再回通过/不通过 |

## 三步走完

| 步 | 你 | 助手 |
| --- | --- | --- |
| 1. 提需求 | 粘贴上面那段 | 小改先写短说明；大改先写方案 |
| 2. 跟着做 | 看「你下一步」；确认时回「准」 | 写代码、做检查 |
| 3. 测一遍 | 按提示测；回通过或不通过 | 收尾；不行继续修 |

文件夹放哪听助手或项目说明即可。进行中的说明多在「未完成」文件里；做完的步骤会进「已完成」。整件事结束时，助手应把文件夹挪出「进行中」，你一般不用手挪。小改如果已经建了文件夹，结束同样要挪走；换一个对话接着做时，助手应接着上次，不要从头再来。

四车道：Express 机械（恰好 1 个文件、无行为变化）/ Direct 默认直通（≤3 文件、不落盘）/ Standard（>3 文件或 API/存档/跨模块）/ Full（完整流程，或标准上再止损）。
标准车道：plan-lite → L1/L1.5/L2 方案审核 → 确认（细节交给助手，见 CORE §四车道 → 派岗）。

## 它可能跟你说的进度

| 它说的意思 | 你要做什么 |
| --- | --- |
| 还在做 | 等，或按提示回复 |
| 请你确认 | 看一轮说明；回「准」就开始改 |
| 请你测试 | 在编辑器里测，或按说明看核对结果 |
| 这段已定 | 若还有下一截，按合并说明再回「准」 |
| 卡住了 | 按说明处理，或找技术负责人 |

## 「准」之后

回「准」后，常规情况会尽量连着做到「等你测」，中间少问选择题。实现↔审查之间不再问你；你要等的停点只有：待验 / AI 验收结果 / 步数上限 / 诊断硬停。测不过时，多数会按推荐继续；特别危险时仍会叫你拍板。**每一步仍要验**。若你只想一步一步来，回「准, 不 Auto」。

## 典故：一提即唤起

- **换模型、换人不失传**：约定好的「典故词」一提，助手就想起整段既定共识，不依赖某个会话的记忆。
- **省复述**：说一个典故词即可，不必每轮把整段共识重讲一遍。
- **验证智慧沉淀**：典故都是经方案审核、代码审核、验收验证过的共识，不是随手摘要。
- **会生长**：本项目留下的结构，回「准」后进本项目表；另说「上传」才交给公共收集仓；升级才收回技能包。装完不是冻住的清单。
- **与辨析表分工**：辨析表防「一个概念多个叫法」（同义异名）；典故节让一个词唤起一整段上下文。

## 典故和错题怎么长到全世界

AI 每测挂一次、每留下一条验过的结构，都是一次进化契机。不是聊天里说过就忘。全世界使用者把各自项目里验过的错题和典故交出去，技能才会一起长。

1. **留下（本项目）**：助手起草错题或典故，你回「准」才进本项目表。回「准」不等于传到网上。
2. **上传（给大家）**：收集仓是公开项目（[ai-gates-collect](https://github.com/zhaobolun-code/ai-gates-collect)）。去项目点名后先进入本机队列。你另说「上传」，并且本机 GitHub 命令行已经登录，就可以开分支、交 pull request（典故、错题分目录，一条一文件，不带你仓库的窗号和路径）。不需要合并权限。没登录就只留在本机。
3. **更新（收回来）**：合并 pull request 要有权限，所以交出去不等于进主线，进主线也不等于你的技能包已更新。维护者抽成通用技能后，你说 `项目经理 升级 ai-gates`，才把全世界已经长好的部分拉回来。

## 常见问题

**要记角色、背口令吗？** 不用。只记「项目经理 + 需求」（`项目经理`=`PM`），确认回「准」。不要直接叫它写代码，从项目经理进。英文会话确认时回 `approve`（=`准`）即可。

**助手会不会用错语言？** 对话和方案正文跟你说话的语言；文件夹名字（如「未完成」）不必改成英文。

**小改也要很长方案吗？** 不用。小改先有一小段说明再改。

**没配置就让它改？** 先说 `项目经理 初始化`。不必手填一整份说明；回归索引可后补。→ 见上文「第一次接入」

**怎么安装 / 更新 / 查版本？**
- 零手动（推荐）：新项目贴 README「快速开始」方式 A 提示词（Agent 联网获取最新版、装库、建传送门）
- 一条命令（开发者/批量）：项目根 PowerShell 运行 `powershell -ExecutionPolicy Bypass -c "irm https://raw.githubusercontent.com/zhaobolun-code/ai-gates/main/scripts/install-ai-gates.ps1 | iex"`（macOS/Linux 暂无对应命令，用方式 A 或手动；无 git 时本命令会自动走 zip 下载）
- 手动（备选）：从 GitHub [Releases](https://github.com/zhaobolun-code/ai-gates/releases/latest) 下载 `ai_dev_<版本号>.7z`（版本以 skills/VERSION 为准），解压到项目根（包内是 `.ai-gates/`，不要解进 `.cursor/`）；解压后说 `项目经理 检查健康` 由 Agent 建好传送门（手动运行 `link-platform.ps1` / `.sh` 亦可，非必需）
- 已装升级：说 `项目经理 升级 ai-gates`（联网比对、有新版才替换）；下载后 Windows 提示「无法运行，拒绝访问」→ 把报错原文粘贴给项目经理处理
- **macOS / Linux 机器 hooks**：脚本全是 `.ps1`，须本机有 **PowerShell 7+（`pwsh`）**；没有 `pwsh` 时只靠规则自觉，**不要当成 hooks 已接线**
- 版本历史见 `.ai-gates/CHANGELOG.md`；体检说 `项目经理 检查健康`

**它乱改、没告诉你下一步？** 回 **`按 CORE 重来`**。

**要不要新开对话再审？** 提示时优先新开（主对话只当「项目经理」，写方案/改代码/再检查多在别的对话里）；留在原对话可以，但独立性差一些。

## 被拦了怎么办（速查）

| 现象 | 原因 | 做法 |
| --- | --- | --- |
| 写入被 deny，提示 `no fresh [PM] marker` | 本会话最近 120 分钟没有过 PM 判定 | 回一句带 `[PM]` 的话（如「[PM] 判定：…」），等打点后重试；或人工确认后放 `.ai-gates/hooks-log/pm-gate-disabled` 临时放行 |
| 写入被 deny，提示 `Level-1` / `CHANGELOG` | 改 `.cursor` / `.ai-gates` 设施前没写 CHANGELOG | 先写 `.ai-gates/CHANGELOG.md`（Included 条目）再重试 |
| Bash 写文件被 deny，提示 `Bash write gate` | 显式写文件没走 PM 门禁 | 改用 apply_patch；或先发 `[PM]` 待打点后重试 |
| `git push --force` / `reset --hard` 被 deny | 高危 git 被机器层硬拦 | 确认安全后在终端手动执行，或临时移除对应 hook 条目 |
| 写完没见到任何门禁痕迹 | 桌面端 apply_patch 钩子可能不触发 | 自查 `.ai-gates/hooks-log/`，或临时用 CLI 会话验证 |
| 流程乱了、想重来 | 没按流程走 | 回 **`按 CORE 重来`** |
