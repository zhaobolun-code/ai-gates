# 使用指南 — 3 分钟上手

> 版本：**v3.3.0**（与 [VERSION](skills/VERSION) 一致）
> 第一次接触：先扫一眼 [METHODOLOGY.md](./METHODOLOGY.md)（能少原地打转、能做完，**不是**万能药）。  
> 新仓库还没配置？先说 **`项目经理 初始化`**，再提需求。

## 你只需要记住一件事

在任一能改文件的 AI 会话里（Cursor 选 Agent 模式；Codex / Trae 同理），粘贴：

```text
项目经理
[描述你要什么 / 遇到什么现象 / 贴报错或截图]
```

也可简写为 `PM`（**`项目经理` = `PM`**）。

**新项目第一次**还可：

```text
项目经理 初始化
```

（**`初始化` = `init`**，故 `PM init` 等组合效果相同。）

升级技能包：`项目经理 升级 ai-gates`（**`升级` = `upgrade`**，`PM upgrade ai-gates`）。  
体检：`项目经理 检查健康`（**`检查健康` = `doctor`**，`PM doctor`）。

不用记各种角色名。助手会用白话告诉你下一步。需要你确认方案、以及测一测时，**仍要你回复**。

> 即使你知道该写代码，也请从「项目经理 + 需求」开始，否则容易漏步骤。

## 对你意味着什么

- **你要做的**：提需求、看确认说明回「准」（=`approve`）、按提示测一遍、说通过或不通过。  
- **你不用做的**：自己改一堆流程文档、自己挪文件夹、背很多角色名。  
- **它不会做的**：不测就保证已经修好；不配置项目就一直好用。

## 基本操作

| 你想… | 怎么做 |
| --- | --- |
| 提需求 | 对话里发「项目经理 + 需求」（`项目经理`=`PM`） |
| 确认可以做 | 回「准」（=`approve`） |
| 让它能改文件 | 模式选 Agent，不要选只读 |
| 单独再审一轮 | 它提示时，新开一个对话，粘贴它给的文字 |
| 在 Unity 里测 | 点播放 → 按步骤操作 → 看控制台 → 停播放 → 回复通过/不通过 |
| 它说本步不用开编辑器 | 看它给的核对结论，再回通过/不通过 |

## 三步走完

| 步 | 你 | 助手 |
| --- | --- | --- |
| 1. 提需求 | 粘贴上面那段 | 小改先写短说明；大改先写方案 |
| 2. 跟着做 | 看「你下一步」；确认时回「准」 | 写代码、做检查 |
| 3. 测一遍 | 按提示测；回通过或不通过 | 收尾；不行继续修 |

文件夹放哪听助手或项目说明即可。进行中的说明多在「未完成」文件里；做完的步骤会进「已完成」。整件事结束时，助手应把文件夹挪出「进行中」，你一般不用手挪。

## 它可能跟你说的进度

| 它说的意思 | 你要做什么 |
| --- | --- |
| 还在做 | 等，或按提示回复 |
| 请你确认 | 看一轮说明；回「准」就开始改 |
| 请你测试 | 在编辑器里测，或按说明看核对结果 |
| 这段已定 | 若还有下一截，按合并说明再回「准」 |
| 卡住了 | 按说明处理，或找技术负责人 |

## 「准」之后

回「准」后，常规情况会尽量连着做到「等你测」，中间少问选择题。测不过时，多数会按推荐继续；特别危险时仍会叫你拍板。**每一步仍要验**。若你只想一步一步来，回「准, 不 Auto」。

## 测试怎么说

```text
测试通过。按步骤验证，现象符合预期。
```

```text
测试不通过。步骤 3 之后仍不对，控制台：[关键词]
```

## 举例

```text
项目经理
登录后点击「开始实验」没反应，控制台有空引用报错
```

```text
项目经理
把某个预制体的碰撞体调大一点，只改预制体
```

## 常见问题

**还要记很多角色吗？** 不用。只记「项目经理 + 需求」（`项目经理`=`PM`）。

**能直接叫它写代码吗？** 不要。从项目经理进。

**小改也要很长方案吗？** 不用。小改先有一小段说明再改。

**没配置就让它改？** 先 `项目经理 初始化`，再填项目说明文件。→ [SKILLS.md](./SKILLS.md)

**它乱改、没告诉你下一步？** 回 **`按 CORE 重来`**。

**要不要新开对话再审？** 它提示时优先听它的；你也可自己新开。留在原对话可以，但独立性差一些。

**主对话干什么？** 主对话只当「项目经理」；写方案、改代码、再检查多在另外的对话里。

**经验总结要我手写吗？** 不用。测不过会先记草稿；正式写入前会再问你「准」。
