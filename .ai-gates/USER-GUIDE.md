# 使用指南

版本以 [VERSION](skills/VERSION) 为准。第一次用：先看 [README.md](./README.md)，再看本文。为什么这样设计、做过哪些记录，在 [METHODOLOGY.md](./METHODOLOGY.md)。

新仓库还没填项目说明时，先说 `项目经理 初始化`，再提需求。

## 你平时怎么开口

在能改文件的会话里粘贴（Cursor 用 Agent 模式；Codex、Trae 同样）：

```text
项目经理
[要做什么 / 看到什么现象 / 报错或截图]
```

`项目经理` 和 `PM` 是一回事。

不用背角色名。助手用你这一会话的语言告诉你下一步。方案要你回「准」，该你试的时候仍要你试。文件夹名字可能仍是中文，不用改。你说没看懂，它会用同样的话再讲一遍。

| 你说 | 也可以说 | 做什么 |
| --- | --- | --- |
| 项目经理 | PM | 加上需求，开始一件事 |
| 准 | approve | 同意这个方案，或同意记下来。不等于传到网上 |
| 初始化 | init | 第一次把项目说明填上 |
| 检查健康 | doctor | 看入口文件和拦截接上没有 |
| 升级 | upgrade | `项目经理 升级 ai-gates`，把技能包更新到新版本 |

英文会话里，确认时回 `approve`。

## 安装和初始化是两步

安装只把文件放进项目、建好传送门（各软件的入口文件）、写下安装信息。初始化才填项目说明和模型。

贴给 Agent 的那段、Windows 一条命令、以及从 [Releases](https://github.com/zhaobolun-code/ai-gates/releases/latest) 手动解压，都写在 [README.md](./README.md)。

Windows 一条命令：

```text
powershell -ExecutionPolicy Bypass -c "irm https://raw.githubusercontent.com/zhaobolun-code/ai-gates/main/.ai-gates/scripts/install-ai-gates.ps1 | iex"
```

macOS / Linux 没有对应的一整套一键命令。`link-platform.sh` 只用来建传送门。机器拦截的脚本都是 `.ps1`，要本机有 PowerShell 7（`pwsh`）。登记的命令名仍是 `powershell`。只有 `pwsh`、没有 `powershell` 时钩子起不来。说 `项目经理 检查健康` 时，若出现 `hooks_not_wired_no_pwsh` 或 `hooks_command_is_powershell`，不要当成已经接上。两个都没有，就只剩对话里的规则。

手动安装：下载 `ai_dev_<版本号>.7z`（版本以 `skills/VERSION` 为准），解压到项目根。包里是 `.ai-gates/`，不要解进 `.cursor/`。解压后说 `项目经理 检查健康`。

已装的升级：说 `项目经理 升级 ai-gates`。有新版才替换。Windows 若提示「无法运行，拒绝访问」，把报错原文贴给项目经理。版本记录在 `.ai-gates/CHANGELOG.md`。

## 第一次填项目说明

说 `项目经理 初始化`。助手会生成项目说明、对齐传送门，并问高档和低档各用哪个模型。你没回答之前，它不会替你填模型名。技术栈由它探测后请你确认。回归索引（必测场景）可以后补。不填也能 `项目经理` 加需求开工；填了，热度升档更准。CodeGraph 可选，要你同意再装。

要能改文件，会话得是 Agent，不要只读。要看业务现象时，通常要能在编辑器里跑起来（例如 Unity 点 Play）。

更细的命令在 [tl-onboarding.md](skills/references/tl-onboarding.md)。

## 你要做的，和不用做的

你要做的是提需求、回「准」、按提示验收。「通过了」这最后一句仍要你说。

助手跟你说话用人话。口令（准、项目经理）和典故词可以保留。典故是已经验证过的做法：提到那个短名字，整段约定和边界一起回来，不用每轮重讲。

你不用自己改一堆流程文档，不用自己挪文件夹，不用背角色名。

机器能跑的检查（编译、回归冒烟、证据归集）会自己跑并留下记录。没跑过的测试不能写成通过。

错题和典故先留在本项目，要你回「准」。回「准」不会上传。去掉本仓库的窗号和路径之后，你另说「上传」，才交给公开收集处。换项目要升级，才能用上已经合并进去的部分。别人项目里的路径和测试清单不能直接拿来用。

## 一件事怎么走

| 步 | 你 | 助手 |
| --- | --- | --- |
| 1. 提需求 | 粘贴上面那段 | 小改先有一小段说明；大改先写方案，该审的先审 |
| 2. 跟着做 | 看「你下一步」；确认时回「准」 | 你回「准」之后才改代码，改完再换一边看 |
| 3. 试一遍 | 按提示试；回通过或不通过 | 收尾；不行就继续修 |

文件夹放哪，听助手或项目说明。进行中的说明多在「未完成」里；做完的步骤进「已完成」。整件事结束时，助手应把文件夹挪出「进行中」，你一般不用手挪。小改如果已经建了文件夹，结束同样要挪走。换一个对话接着做时，应接着上次，不要从头再来。

松紧它自己选。恰好一个业务文件，只改注释、已有日志或不超过 3 行的常量，而且不改变行为，走 Express。有行为变化，或两到三个文件、不碰接口、存档、跨模块，走 Direct，这是默认。超过三个文件，或跨模块、接口、存档、说不清，走 Standard。Express 或 Direct 第一次反复失败，也会升到 Standard。更严的强制条件走 Full，按 CORE 判定，不在这里概括。Standard 和 Full 先写方案，审过再等你确认：`plan-lite → L1/L1.5/L2 方案审核 → 确认`。判完只读其中一张说明。

## 它可能跟你说的进度

| 它说的意思 | 你要做什么 |
| --- | --- |
| 还在做 | 等，或按提示回复 |
| 请你确认 | 看一轮说明；回「准」就开始改 |
| 请你测试 | 在编辑器里测，或按说明看核对结果 |
| 这段已定 | 若还有下一截，按合并说明再回「准」 |
| 卡住了 | 按说明处理，或找技术负责人 |

回「准」之后，常规情况会尽量连着做到等你测，中间少问选择题。实现和审查之间不再问你。你要等的停点是：待验、AI 验收结果、步数上限、诊断硬停。测不过时，多数会按推荐继续；特别危险时仍会叫你拍板。每一步仍要验。若你只想一步一步来，回「准, 不 Auto」。

## 测试怎么说

```text
测试通过。按步骤验证，现象符合预期。
```

```text
测试不通过。步骤 3 之后仍不对，控制台：[关键词]
```

举例：

```text
项目经理
登录后点击「开始实验」没反应，控制台有空引用报错
```

```text
项目经理
把某个预制体的碰撞体调大一点，只改预制体
```

## 基本操作

| 你想… | 怎么做 |
| --- | --- |
| 提需求 | 对话里发「项目经理」加上需求 |
| 确认可以做，或留下错题、典故 | 回「准」。不等于传到网上 |
| 把本项目的典故或错题交出去 | 另说「上传」。公开收集仓是 [ai-gates-collect](https://github.com/zhaobolun-code/ai-gates-collect)。本机 GitHub 命令行已登录才能开分支、交 pull request。典故和错题分目录，一条一个文件，不带窗号和路径。没登录就只留在本机。合并要有权限，交出去不等于进主线 |
| 把已经合并的部分拉回来 | `项目经理 升级 ai-gates` |
| 对照网上类似项目 | 它提示时回「外仓对照」。不点名不会去搜、不会下载。外仓代码不许直接复制 |
| 让它能改文件 | 模式选 Agent，不要选只读 |
| 单独再审一轮 | 它提示时，新开一个对话，粘贴它给的文字。留在原对话可以，独立性差一些 |
| 在 Unity 里测 | 点播放，按步骤操作，看控制台，停播放，回复通过或不通过 |
| 跑自动化测试 | 仓库根有 `Tests/EditMode/` 时，在项目根运行 `powershell -ExecutionPolicy Bypass -File .ai-gates/scripts/run-dotnet-editmode-tests.ps1`。total≥70 且 failed=0 才算绿。秒级，不占 Unity。断言绿不等于业务通过 |
| 它说本步不用开编辑器 | 看它给的核对结论，再回通过或不通过 |
| 打开或更新迷雾地图 | 文档状态变了之后，助手会问要不要创建或更新。你同意后再生成。双击 `.ai-gates/verify/fog-map.html`。直接打开文件，不要另开网页服务，也不要改这张网页。别的目录里的旧图不要用 |
| 打开会话看板 | 运行 `powershell -ExecutionPolicy Bypass -File .ai-gates/scripts/generate-session-dash.ps1`，再双击 `.ai-gates/verify/session-dash.html`。直接打开，不要另开网页服务。这不是账单 |
| 流程乱了 | 回 `按 CORE 重来` |

## 错题和典故

测试没过先留下记录。修好后你回「准」，才写入这个项目。以后写方案会先看相关错题。再碰到类似的地方，审查会更严。

做成并且验过的做法，起一个短名字，叫典故。以后提到这个名字，约定和边界一起回来。换模型、换人也不用重讲。它不是随手写的摘要。

回「准」只写入本项目。你另说「上传」，并且本机 GitHub 命令行已经登录，才开分支交给收集仓。维护者合并之后，你说 `项目经理 升级 ai-gates`，才能把那部分拉回来。交出去不等于已经进主线，进主线也不等于你这边已经更新。

## 被拦了怎么办

| 现象 | 原因 | 做法 |
| --- | --- | --- |
| 写入被拒绝，提示 `no window_pm` / `no fresh [PM]` | 本会话 120 分钟内没有 `[PM]` 打点。机器层叫 window_pm，不是「这一条已经判定完」 | 主窗回一句带 `[PM]` 的话，等打点后重试。子窗不要发 `[PM]`，等主窗打点或主窗代写。或放 `.ai-gates/hooks-log/pm-gate-disabled` 临时放行 |
| 窗口内放过了，流程仍说缺判定 | 机器放行不等于这一条已经做完判定 | 本条回复仍须带结构化 `[PM]` 和「你下一步」。不要把 120 分钟窗口当成已经判过 |
| 写入被拒绝，提示 `Level-1` / `CHANGELOG` | 改设施前没写变更日志 | 先写 `.ai-gates/CHANGELOG.md` 再重试。顺序见 [MAINTAINER.md](skills/MAINTAINER.md) 文首 |
| 终端写文件被拒绝，提示 `Bash write gate` | 这次写入没经过开工标记 | 改走编辑器里的改文件方式；或先发 `[PM]`，打点后再试 |
| `git push --force` / `reset --hard` 被拒绝 | 高危 git 被拦住 | 确认安全后在终端自己执行，或临时拿掉对应的拦截条目 |
| 写完没有任何拦截痕迹 | Codex 桌面的 `apply_patch` 可能不触发。Cursor 桌面一般会触发 | 看 `.ai-gates/hooks-log/`，或换命令行会话再试 |
| Trae 里改文件没有机器拒绝 | Trae 没有机器拦截，只靠规则 | 这一条仍要带 `[PM]`。不要把「本机有 powershell」当成 Trae 已接上 |
| 流程乱了 | 没按流程走 | 回 `按 CORE 重来` |

命令认不出、状态文件读坏时，这道检查会放过。拦截不是绝对边界。
