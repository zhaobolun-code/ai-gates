# 使用指南

版本以 [VERSION](skills/VERSION) 为准。第一次用：先看 [README.md](./README.md)，再看本文。为什么这样设计、做过哪些记录，在 [METHODOLOGY.md](./METHODOLOGY.md)。

新仓库还没填项目说明时，先说 `初始化`，再提需求。装上 ai-gates 之后，直接说要做什么。它会先读常驻卡，不必先写「项目经理」或「PM」。

## 你平时怎么开口

在能改文件的会话里直接写（Cursor 用 Agent 模式；Codex、Trae 同样）：

```text
[要做什么 / 看到什么现象 / 报错或截图]
```

不用背角色名。助手用你这一会话的语言告诉你下一步。方案要你回「准」，该你试的时候仍要你试。文件夹名字可能仍是中文，不用改。你说没看懂，它会用同样的话再讲一遍。

| 你说 | 也可以说 | 做什么 |
| --- | --- | --- |
| 准 | approve | 同意这个方案，或同意记下来。不等于传到网上 |
| 初始化 | init | 第一次把项目说明填上 |
| 检查健康 | doctor | 看入口文件和拦截接上没有，并核对有没有新版本 |
| 升级 ai-gates | | 把技能包更新到新版本 |

英文会话里，确认时回 `approve`。

## 安装和初始化是两步

安装只把文件放进项目、建好传送门（各软件的入口文件）、写下安装信息。初始化才填项目说明和模型。

贴给 Agent 的那段、Windows 一条命令、以及从 [Releases](https://github.com/zhaobolun-code/ai-gates/releases/latest) 手动解压，都写在 [README.md](./README.md)。

Windows 一条命令：

```text
powershell -ExecutionPolicy Bypass -c "irm https://raw.githubusercontent.com/zhaobolun-code/ai-gates/main/.ai-gates/scripts/install-ai-gates.ps1 | iex"
```

macOS / Linux 没有对应的一整套一键命令。`link-platform.sh` 只用来建传送门。机器拦截的脚本都是 `.ps1`，要本机有 PowerShell 7（`pwsh`）。登记的命令名仍是 `powershell`。只有 `pwsh`、没有 `powershell` 时钩子起不来。说 `检查健康` 时，若出现 `hooks_not_wired_no_pwsh` 或 `hooks_command_is_powershell`，不要当成已经接上。两个都没有，就只剩对话里的规则。

手动安装：下载 `ai_dev_<版本号>.7z`（版本以 `skills/VERSION` 为准），解压到项目根。包里是 `.ai-gates/`，不要解进 `.cursor/`。解压后说 `检查健康`。

已装的升级：说 `升级 ai-gates`。有新版才替换。已有项目说明缺常用命令、仓库分仓、客户端事实时补上空节，不覆盖已经写上的内容。Windows 若提示「无法运行，拒绝访问」，把报错原文贴回对话。版本记录在 `.ai-gates/CHANGELOG.md`。

## 第一次填项目说明

说 `初始化`。助手会生成项目说明、对齐传送门，并问高档和低档各用哪个模型。你没回答之前，它不会替你填模型名。技术栈由它探测后请你确认。回归索引（必测场景）可以后补。不填也能直接说需求开工。填了，你确认走标准道之后，方案审按模块热度分档。CodeGraph 可选，要你同意再装。

要能改文件，会话得是 Agent，不要只读。要看业务现象时，通常要能在编辑器里跑起来（例如 Unity 点 Play）。

更细的命令在 [tl-onboarding.md](skills/references/tl-onboarding.md)。

## 你要做的，和不用做的

你要做的是提需求。要换车道，或同意标准道、完整流程的方案时，回「准」。按提示验收。「通过了」这最后一句仍要你说。

助手跟你说话用人话。口令（准、初始化、检查健康、升级 ai-gates）和典故词可以保留。典故是已经验证过的做法：提到那个短名字，整段约定和边界一起回来，不用每轮重讲。

你不用自己改一堆流程文档，不用自己挪文件夹，不用背角色名。

机器能跑的检查（编译、回归冒烟、证据归集）会自己跑并留下记录。没跑过的测试不能写成通过。

错题和典故先留在本项目，要你回「准」。回「准」不会上传。去掉本仓库的窗号和路径之后，你另说「上传」，才交给公开收集处。换项目要升级，才能用上已经合并进去的部分。别人项目里的路径和测试清单不能直接拿来用。

## 和 5.4.0 的差别

6.0.0 路由是四条，默认快车道。人点名「Auto车道」才启动那套做法，不写入路由。近 20 天将改的文件失败次数到 2，建议直通；到 4，建议标准道；到 6，建议完整流程。最近一次须是失败。你确认或点名，这一刀才换。你不回，就停在快车道。

| | 5.4.0 | 6.0.0 |
| --- | --- | --- |
| 没点名车道时 | 少于 3 个业务文件，且不是在设计核心逻辑，走快车道。3 个及以上，或这刀在设计核心逻辑，走直通。接口、存档、跨模块、说不清，升标准道。快车道命中止损，也升标准道。核心逻辑指新写或改写判定、控制流、守恒、通断或方向 | 文件个数、是不是核心逻辑、接口、存档、跨模块、说不清、止损，都不改标签。只按失败次数写建议 |
| 你不回建议 | 上面这些条件直接定档 | 停在快车道 |
| 人点名「Auto车道」 | 没有这一条 | 不进四条路由。要你点名才启动。先问清，你回「准」后写文档，用 UnitySkills 先测、再改、再测，同一失败连续 3 次就停。通过后隔离审，你再回一次「准」才提交。你没点名，停在快车道 |

## 一件事怎么走

| 步 | 你 | 助手 |
| --- | --- | --- |
| 1. 提需求 | 直接说要做什么，或贴现象 | 已经说出改哪一行、改成什么，同条就改。你确认标准道或完整流程之后，才先写方案，该审的先审 |
| 2. 跟着做 | 看「你下一步」；要换车道或同意方案时回「准」 | 快车道上，改哪一行已经说清就直接改。标准道和完整流程要等你回「准」再改代码，改完再换一边看 |
| 3. 试一遍 | 按提示试；回通过或不通过 | 收尾；不行就继续修 |

文件夹放哪，听助手或项目说明。进行中的说明多在「未完成」里；做完的步骤进「已完成」。整件事结束时，助手应把文件夹挪出「进行中」，你一般不用手挪。小改如果已经建了文件夹，结束同样要挪走。换一个对话接着做时，应接着上次，不要从头再来。

已经说出改哪一行、改成什么的，同条就改。你确认了标准道或完整流程之后，才先写方案，审过再等你回「准」：`plan-lite → L1/L1.5/L2 方案审核 → 确认`。判完只读其中一张说明。停写默认关。`治理信号` 和 `治理选择` 只在单独成行时记入不稳度账，开工仍直接说需求。

## 它可能跟你说的进度

| 它说的意思 | 你要做什么 |
| --- | --- |
| 还在做 | 等，或按提示回复 |
| 请你确认 | 看一轮说明；回「准」就开始改 |
| 请你测试 | 在编辑器里测，或按说明看核对结果 |
| 这段已定 | 若还有下一截，按合并说明再回「准」 |
| 卡住了 | 按说明处理，或找技术负责人 |

## 测试怎么说

```text
测试通过。按步骤验证，现象符合预期。
```

```text
测试不通过。步骤 3 之后仍不对，控制台：[关键词]
```

举例：

```text
登录后点击「开始实验」没反应，控制台有空引用报错
```

```text
把某个预制体的碰撞体调大一点，只改预制体
```

## 基本操作

| 你想… | 怎么做 |
| --- | --- |
| 提需求 | 对话里直接说需求 |
| 确认可以做，或留下错题、典故 | 回「准」。不等于传到网上 |
| 把本项目的典故或错题交出去 | 另说「上传」。公开收集仓是 [ai-gates-collect](https://github.com/zhaobolun-code/ai-gates-collect)。本机 GitHub 命令行已登录才能开分支、交 pull request。典故和错题分目录，一条一个文件，不带窗号和路径。没登录就只留在本机。合并要有权限，交出去不等于进主线 |
| 把已经合并的部分拉回来 | `升级 ai-gates` |
| 对照网上类似项目 | 它提示时回「外仓对照」。不点名不会去搜、不会下载。外仓代码不许直接复制 |
| 让它能改文件 | 模式选 Agent，不要选只读 |
| 单独再审一轮 | 它提示时，新开一个对话，粘贴它给的文字。留在原对话可以，独立性差一些 |
| 在 Unity 里测 | 点播放，按步骤操作，看控制台，停播放，回复通过或不通过 |
| 跑自动化测试 | 仓库根有 `Tests/EditMode/` 时，在项目根运行 `powershell -ExecutionPolicy Bypass -File .ai-gates/scripts/run-dotnet-editmode-tests.ps1`。total≥70 且 failed=0 才算绿。秒级，不占 Unity。断言绿不等于业务通过 |
| 它说本步不用开编辑器 | 看它给的核对结论，再回通过或不通过 |
| 打开或更新迷雾地图 | 文档状态变了之后，助手会问要不要创建或更新。你同意后再生成。双击 `.ai-gates/verify/fog-map.html`。直接打开文件，不要另开网页服务，也不要改这张网页。别的目录里的旧图不要用 |
| 打开会话看板 | 运行 `powershell -ExecutionPolicy Bypass -File .ai-gates/scripts/generate-session-dash.ps1`，再双击 `.ai-gates/verify/session-dash.html`。直接打开，不要另开网页服务。这不是账单 |
| 流程乱了 | 回 `按 CORE 重来` |

## 错题和典故

测试没过先留下记录。修好后你回「准」，才写入这个项目。以后写方案会先看相关错题。再碰到类似的地方，审查会更严。

做成并且验过的做法，起一个短名字，叫典故。以后提到这个名字，约定和边界一起回来。换模型、换人也不用重讲。它不是随手写的摘要。

回「准」只写入本项目。你另说「上传」，并且本机 GitHub 命令行已经登录，才开分支交给收集仓。维护者合并之后，你说 `升级 ai-gates`，才能把那部分拉回来。交出去不等于已经进主线，进主线也不等于你这边已经更新。

## 被拦了怎么办

| 现象 | 原因 | 做法 |
| --- | --- | --- |
| 业务代码被这道写门拒绝 | 业务路径不再查 `[PM]`。放行代号是 `business_write`。同一窗、同一验收条款、同一句现象已经热修 2 次，详情是 `third_hotfix` | 看拒绝详情。窗、验收条款、现象对不上，或这一刀车道已经换了，这道拒绝不发生 |
| 放行了，流程仍要你确认 | 放行不说明判定做完，也不说明审过或验收过 | 看「你下一步」。标准道和完整流程仍回「准」 |
| 写入被拒绝，提示 `Level-1` / `CHANGELOG` | 改设施前没写变更日志。Level 1 放行只证明本会话 120 分钟内写过正式 CHANGELOG.md，不证明条目描述了即将修改的文件或内容 | 先写 `.ai-gates/CHANGELOG.md` 再重试。顺序见 [MAINTAINER.md](skills/MAINTAINER.md) 文首 |
| 终端写文件被拒绝，提示 `Bash write gate` | 终端写文件走同一道门。业务路径不查 `[PM]`。设施路径要本会话 120 分钟内的变更日志 | 业务代码改用编辑器里的改文件。改设施先写 `.ai-gates/CHANGELOG.md` |
| 要临时关掉写门 | 空文件和 Agent 写入不算 | 在本机终端（不要经过 Agent）运行 `.ai-gates/scripts/enable-kill-switch.ps1`，按提示输入 ENABLE KILL SWITCH |
| `git push --force` / `reset --hard` 被拒绝 | 高危 git 被拦住 | 确认安全后在终端自己执行，或临时拿掉对应的拦截条目 |
| 写完没有任何拦截痕迹 | Codex 桌面的 `apply_patch` 可能不触发。Cursor 桌面一般会触发 | 看 `.ai-gates/hooks-log/`，或换命令行会话再试 |
| Trae 里改文件没有机器拒绝 | Trae 没有机器拦截，规则还在 | 不要把「本机有 powershell」当成 Trae 已接上 |
| 流程乱了 | 没按流程走 | 回 `按 CORE 重来` |

命令认不出、状态文件读坏时，这道检查会放过。拦截不是绝对边界。
